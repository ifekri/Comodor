# از WhatsApp

همان ایجنت، که از یک شماره‌ی تجاری WhatsApp به آن می‌رسید: برایش کار بفرستید، کار
کردنش را ببینید، به پرسش‌هایش پاسخ دهید — بدون باز کردن ترمینال.

> **این را نخست بخوانید.** [Telegram](telegram.md) همان کار را می‌کند و حدود یک
> دقیقه وقت می‌گیرد: به @BotFather پیام بدهید، یک توکن بچسبانید. WhatsApp حدود
> بیست دقیقه است، فنی است، و بیشترش در داشبورد Meta می‌گذرد — به یک اپ Meta، یک
> رمز اپ و یک نشانی عمومی HTTPS نیاز دارید. **اگر لزوماً نباید WhatsApp باشد، از
> Telegram استفاده کنید.**
>
> [Slack](slack.md) راه میانه است: حدود پنج دقیقه، و نشانی عمومی هم نمی‌خواهد.
>
> هیچ راهی دور زدنش نیست. WhatsApp معادلی برای توکن ربات ندارد، و Meta پیام‌ها
> را به یک URL تحویل می‌دهد، نه اینکه اجازه دهد چیزی برایشان پول بزند. تنها
> نسخه‌ی واقعاً یک‌کلیکی، عبور دادن تک‌تک پیام‌ها از سرور کس دیگری می‌شد، که
> معامله‌ای نیست که این ابزار بکند.

```bash
comodor whatsapp connect              # walks you through all of it
comodor whatsapp pair                 # add your number
comodor whatsapp start --background   # run it
```

`connect` بدون آرگومان یک راه‌اندازی هدایت‌شده است: هر صفحه را پیوند می‌دهد،
یک بار یک مقدار می‌گیرد، و هر یک را همان‌طور که می‌رسد بررسی می‌کند — توکن را
با Meta، شناسه را برای اینکه شناسه باشد، رمز را برای اینکه رمز باشد. تونل را
برای شما اجرا می‌کند، و منتظر می‌ماند فراخوانی بازخورد تأیید Meta واقعاً برسد،
نه اینکه فرض کند رسیده است.

همان نشست ایجنتی را اجرا می‌کند که ترمینال، مرورگر و ربات Telegram اجرا می‌کنند.
کاری که اینجا آغاز شود همان درس‌ها را می‌آموزد و در همان تاریخچه ظاهر می‌شود.

## چرا این بیشتر از Telegram راه‌اندازی می‌خواهد

Telegram یک توکن به شما می‌دهد و اجازه می‌دهد برای پیام‌ها پول بزنید. WhatsApp
همان **Cloud API** متاست، و دو تصمیم طراحیِ آن همه چیزِ اینجا را شکل می‌دهد.

**پیام‌ها تحویل داده می‌شوند، نه گرفته می‌شوند.** پول طولانی‌مدتی وجود ندارد.
Meta هر پیام ورودی را به یک URL می‌فرستد، یعنی چیزی از آنِ شما باید از اینترنت
روی HTTPS در دسترس باشد. آن کار اضافی است، و راهی دور زدنش نیست.

**Meta یک اپ می‌خواهد.** یک حساب تجاری، یک شماره، یک توکن دسترسی و یک رمز اپ —
چهار چیزی که در یک مرورگر زندگی می‌کنند، و به همین دلیل است که جادوگرِ نخستین
اجرا به این صفحه اشاره می‌کند، به‌جای آنکه بخواهد آن‌ها را جمع کند.

راهی که بیشتر پروژه‌ها به سراغش می‌روند کتابخانه‌ای است که WhatsApp Web را از
طریق یک مرورگر بی‌سر می‌راند. آن‌ها Node می‌خواهند، هر بار که WhatsApp کلاینت
وبش را عوض کند می‌شکنند، و خلاف شرایطی هستند که حساب بر اساس آن نگه داشته می‌شود:
حالت شکست، بن شدن شماره است. چیزی که یک ابزار کدنویسی حق ندارد به کاربرانش بدهد.

## چقدر طول می‌کشد

نخستین بار حدود بیست دقیقه، در برابر یک دقیقه برای Telegram، و بیشترش در
داشبورد Meta می‌گذرد، نه اینجا.

آنچه **لازم نیست**: یک شماره‌ی تلفن واقعی، یک شیوه‌ی پرداخت، یا تأیید کسب‌وکار.
اضافه کردن محصول WhatsApp یک **شماره‌ی آزمایشی** می‌سازد که تا پنج گیرنده را
رایگان پیام می‌کند، که چهار تا بیشتر از آن چیزی است که یک نفر که با ایجنت خودش
حرف می‌زند لازم دارد.

## راه‌اندازی

نسخه‌ی کوتاهش `comodor whatsapp connect` است که تمام مسیر را با شما طی می‌کند.
آنچه در ادامه می‌آید همان مسیری است که می‌پیماید، برای هر کسی که ترجیح می‌دهد
نخست ببیندش.

### ۱. یک اپ Meta با WhatsApp روی آن

در [developers.facebook.com](https://developers.facebook.com) یک اپ بسازید و
محصول **WhatsApp** را اضافه کنید. Meta برای شروع یک شماره‌ی آزمایشی به شما
می‌دهد؛ شماره‌ی واقعی بعداً زیر حساب تجاری اضافه می‌شود.

چهار چیز از آنجا لازم دارید:

| | |
|---|---|
| **شناسه‌ی شماره‌ی تلفن** | شناسه‌ی عددی کنار شماره — *نه* خود شماره |
| **توکن دسترسی** | توکنِ خودِ داشبورد ۲۴ ساعت دوام دارد. توکنِ یک **System User** زیر Business Settings منقضی نمی‌شود، و همان است که باید استفاده کنید |
| **رمز اپ** | Settings → Basic. هر وب‌هوک با آن امضا می‌شود |
| **یک نشانی عمومی HTTPS** | جایی که Meta تحویل می‌دهد. پایین‌تر ببینید |

```bash
comodor whatsapp connect \
    --number-id 123456789012345 \
    --token EAAG… \
    --app-secret 0a1b2c…
```

پیش از ذخیره‌ی هر چیزی توکن را با Meta بررسی می‌کند، پس یک غلط تایپی، همین حالا
یک پیام است، نه یک معمای هفته‌ی بعد.

### ۲. جایی که Meta به آن تحویل دهد

ربات روی `127.0.0.1:8770` گوش می‌دهد. Meta تنها به **HTTPS** تحویل می‌دهد و
گواهی self-signed را نمی‌پذیرد، پس چیزی باید یک گواهی واقعی جلوی آن بگذارد.
تونل، پاسخ همیشگی است: بدون پورت باز، بدون DNS، بدون دامنه.

**`comodor whatsapp connect` این را برایتان می‌کند** اگر `cloudflared` نصب
باشد — تونل را اجرا می‌کند، نشانی را از آن بیرون می‌کشد، و نشان می‌دهد چه چیزی
را باید بچسبانید. برای اجرای خودتان:

```bash
cloudflared tunnel --url http://127.0.0.1:8770
comodor whatsapp connect --url https://something.trycloudflare.com/whatsapp
comodor whatsapp webhook
```

**یک تونل سریع در هر اجرا نشانی تازه می‌گیرد.** حین راه‌اندازی اشکالی ندارد و
برای رباتی که قرار است ادامه دهد اشتباه است: Meta به تحویل دادن به نشانی‌ای که
به او داده‌اید ادامه می‌دهد، پس پس از یک ری‌استارت هیچ چیزی نمی‌رسد و هیچ چیز
نمی‌گوید چرا. `comodor whatsapp start --tunnel` وقتی نشانی جابه‌جا شده هشدار
می‌دهد.

برای نشانی‌ای که می‌ماند، یک بار یک تونل نام‌دار بسازید — یک حساب رایگان
Cloudflare می‌خواهد:

```bash
cloudflared tunnel login
cloudflared tunnel create comodor
cloudflared tunnel route dns comodor comodor-hooks.example.com
```

هر چیز دیگری که TLS را پایان می‌دهد و به `127.0.0.1:8770` می‌فرستد، به همان
شکل کار می‌کند.

```
  Callback URL   https://something.trycloudflare.com/whatsapp
  Verify token   Kq3nP…
```

هر دو را در **WhatsApp → Configuration** در داشبورد بچسبانید، سپس اپ را به فیلد
**messages** مشترک کنید. Meta بلافاصله یک بار URL را برای بررسی فرامی‌خواند؛
ربات خودش به آن دست‌دادن پاسخ می‌دهد.

یک پروکسی معکوس که از قبل اجرایش می‌کنید به همان شکل کار می‌کند — هر چیزی که
TLS را پایان می‌دهد و به `127.0.0.1:8770` می‌فرستد.

### ۳. شماره‌ی خودتان را جفت کنید

```bash
comodor whatsapp pair
```

یک کد شش‌رقمی چاپ می‌کند. آن را از WhatsApp به شماره‌ی تجاری بفرستید و شماره‌ی
شما اضافه می‌شود. کد یک‌بار کار می‌کند و در پنج دقیقه منقضی می‌شود.

**یک شماره‌ی تجاری یک شماره‌ی تلفن است**، و غریبه‌ها به‌روالِ عادت به شماره‌های
تلفن پیام می‌دهند. پس تنها به یک فهرست ثابت پاسخ می‌دهد و بقیه همه **سکوت**
می‌گیرند — نه یک رد. شماره‌ای که بگوید «شما مجاز نیستید» به یک غریبه گفته که
ارزش تلاش دوباره را دارد.

```bash
comodor whatsapp status         # who may talk to it
comodor whatsapp forget 15551234567
comodor whatsapp forget all
```

فهرست به‌صورت رقم مقایسه می‌شود، پس `+1 555…` و `001 555…` و `1555…` یک نفرند،
نه سه نفر.

## چه می‌تواند بکند، و چه نمی‌تواند

**به‌طور پیش‌فرض می‌خواند و برنامه می‌ریزد، و چیزی تغییر نمی‌دهد.** یک نشست
WhatsApp فارغ از تنظیم ترمینال، در حالت plan نگه داشته می‌شود، به همان دلیلِ
Telegram: تأیید یک فرمان پوسته با شست، در صف، تصمیمی است که با توجهی کمتر از
همان تأیید روی صفحه‌کلید گرفته می‌شود.

```bash
comodor whatsapp writes on
comodor whatsapp writes off
```

این از عمد یک فرمان ترمینال است. رباتی که می‌توانست مجوزهای خودش را گسترش دهد
تنها به گوشی یک نفر نیاز داشت.

## دکمه‌ها

WhatsApp اجازه‌ی **سه** دکمه‌ی پاسخِ بیست‌کاراکتری می‌دهد، یا یک دکمه که فهرستی
از **ده** ردیف را باز می‌کند. این‌ها سقف‌های سخت‌گیرانه‌اند — Meta کل پیام را رد
می‌کند، نه اینکه کوتاهش کند — پس منو یک فهرست است، و دقیقاً ده ردیف است:

| | |
|---|---|
| **چت جدید** | فراموش کردن گفتگوی تاکنونی |
| **تاریخچه** | بازگشایی یک گفتگوی پیشین |
| **حالت** | عمل، برنامه یا چت |
| **وضعیت** | مدل، پوشه، زمینه، خرج |
| **مدل** | تغییر به مدل دیگر |
| **پوشه** | در کدام پروژه کار می‌کند |
| **مهارت‌ها** | نصب یا حذف یکی |
| **قواعد** | چه آموخته از اصلاحات شما |
| **چه کاری مجاز است** | آیا می‌تواند ویرایش و اجرا کند |
| **راهنما** | هر چیز چه می‌کند |

وقتی کاری در حال اجراست تنها چیزی که پیشنهاد می‌شود **توقف** است: در صفحه‌ای
این‌قدر باریک جایی نیست که یک کنترل را خاکستری نگه داشت.

فهرست‌های بلندتر — مدل‌ها، مهارت‌ها، تاریخچه — هشت‌تا هشت‌تا صفحه‌بندی می‌شوند،
چون دو ردیف ناوبری جزو همان ده تا حساب می‌شوند.

## دو چیز که شما را غافلگیر می‌کند

**نمی‌تواند پیامی را ویرایش کند.** Telegram پاسخ را با بازنویسی یک پیام جریانی
می‌کند همان‌طور که جواب می‌رسد. WhatsApp ویرایش ندارد، و یک پیام به‌ازای هر
توکن صد اعلان برای یک پرسش می‌شد. پس یک نوبت وقتی آغاز می‌شود یک خط می‌گوید،
حین کار گاه‌گاهی چیزی می‌گوید، و جواب را وقتی وجود دارد می‌فرستد.

**یک پنجره‌ی یک‌روزه هست.** Meta پیام‌های آزاد را تنها درون بیست‌وچهار ساعت از
آخرین پیام *شما* اجازه می‌دهد. اگر کاری طولانی پس از آن تمام شود، ربات
نمی‌تواند به شما بگوید — در گزارشش همین را می‌گوید، و دوباره نوشتن به آن پنجره
را دوباره باز می‌کند.

## اجرایش

دقیقاً مثل Telegram:

```bash
comodor whatsapp start                # here, holding this terminal
comodor whatsapp start --tunnel       # and bring a tunnel up with it
comodor whatsapp start --background   # detached; survives closing it
comodor whatsapp stop
comodor whatsapp service install      # starts at login, survives a reboot
comodor whatsapp service show         # read the unit before trusting it
```

گزارش `whatsapp.log` کنار پیکربندی شماست، به آن اضافه می‌شود نه اینکه جایگزین
شود.

روی هر پلتفرم یک سرویس **کاربری** — systemd، launchd، Task Scheduler — هرگز یک
سرویس سیستمی. این ایجنتی است که با اعتبارنامه‌های شما فایل‌هایتان را می‌خواند و
می‌نویسد، و اختیارِ بیشتر از شخصی که مالک آن فایل‌هاست هیچ چیز نمی‌خرد.

## چگونه ساخته شده

بدون وابستگی تازه. Cloud API یک `POST /messages` روی کلاینت HTTP‌ای است که این
پروژه از پیش دارد، و وب‌هوک `http.server` از کتابخانه‌ی استاندارد است.

نقطه‌ی پایانی به Meta **پیش از** انجام کار پاسخ می‌دهد. Meta هر چیزی را که برایش
200 نگیرد در عرض چند ثانیه دوباره می‌فرستد، و یک نوبت ایجنت چند دقیقه طول
می‌کشد — وب‌هوکی که منتظر می‌ماند، همان پیام را پنج بار تحویل می‌گیرد.

شناسه‌های پیام به یاد سپرده می‌شوند، پس تحویلی که به هر حال از نو برسد به یک نوبت
دوم تبدیل نمی‌شود.

## آنچه انجام نمی‌دهد

- پاسخ دادن به هر کسی که جفت نشده، یا گفتن اینکه چرا.
- پذیرفتن وب‌هوکی که نمی‌تواند راستی‌آزمایشش کند. بدون رمز اپ هیچ چیز
  راستی‌آزمایش نمی‌شود، و `comodor whatsapp status` همین را به زرد می‌گوید.
- گرفتن توکن، شماره یا حسابی مجاز از `.comodor/config.json` یک پروژه. مخزنی که
  بتواند نویسنده‌اش را به آن فهرست اضافه کند یک درِ پشتی می‌شد.
- ویرایش هیچ چیز تا وقتی `whatsapp writes on` نشده.
- چاپ توکن. از هر خطایی که برانگیخته می‌شود پیراسته شده است.
