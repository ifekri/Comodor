# مدل‌ها روی ماشین خودتان

Comodor می‌تواند مدلی را دانلود کند، روی دیسک شما نگهش دارد، و آنجا اجرایش کند —
بدون کلید، بدون حساب، و با قطع بودن شبکه همچنان کار می‌کند.

```bash
comodor local list                       # what you can run, and what is here
comodor local get qwen2.5-coder-7b-q4    # download it, with a progress bar
comodor local use qwen2.5-coder-7b-q4    # make it the one the agent talks to
```

همان فهرست در مرورگر زیر **Admin → Local LLM** است، با همان دانلود، همان پیشرفت
و همان دکمه‌ها.

## چگونه سر هم آمده، و چرا کند نیست

هر چیزی که معتبر است همان کار را می‌کند — Ollama، LM Studio، llama.cpp، vLLM —
و Comodor هم می‌کند: **استنتاج در یک فرآیند جداگانه اجرا می‌شود که با یک API
سازگار با OpenAI صحبت می‌کند، و مدل میان درخواست‌ها درون آن بارگذاری‌شده
می‌ماند.**

سه دلیل، همه درباره‌ی پاسخ‌گو ماندن ایجنت:

**GIL.** تولید یک حلقه‌ی طولانیِ محدود به CPU است. آن را در فرآیند خودِ Comodor
اجرا کنید و هر رشته‌ی دیگر — بازترسیم رابط، تمام شدن یک ابزار، اتوبوس رویداد —
پشتش منتظر می‌ماند. در فرآیند دیگر، مشکلِ هسته‌ی دیگری است.

**بارگذاری پرهزینه است و باید یک بار رخ دهد.** خواندن چهار گیگابایت از دیسک و
چیدن آن، ثانیه‌ها تا ده‌ها ثانیه طول می‌کشد. بارگذاری به‌ازای هر درخواست این را
در هر نوبت می‌پردازد؛ یک سرور مقیم یک بار می‌پردازد و پس از آن در حد
میلی‌ثانیه پاسخ می‌دهد.

**یک کرش همان‌جا می‌ماند.** یک کشتنِ کمبود حافظه روی مدلی 14B، سرور مدل را
پایان می‌دهد، نه نشست شما را. ایجنت یک خطای اتصال را گزارش می‌کند و گزارش گفتگو
جان به در می‌برد.

پیامد خوشحال‌کننده این است که تقریباً هیچ کد تازه‌ای نیست: یک سرور محلی روی
`http://127.0.0.1:PORT/v1` *خودش* یک نقطه‌ی پایانی سازگار با OpenAI است، پس
ارائه‌دهنده‌ی موجود، بدون تغییر، آن را می‌راند. پورت هنگام شروع سرور انتخاب
می‌شود، و به همین دلیل است که ارائه‌دهنده‌ی `local` در پیکربندی URL‌ای حمل
نمی‌کند — یکی که آنجا نوشته می‌شد، بار بعد غلط بود.

سرور با **نخستین پیام** شما اجرا می‌شود، نه هنگام شروع. بارگذاری چهار گیگابایت
هر بار که `comodor` را اجرا می‌کردید — حتی آن بارها که هیچ چیز از مدل نپرسیده
بودید — یک صفحه‌ی سیاه بی‌دلیل می‌شد.

## چه چیزی لازم دارید

فایل مدل، که Comodor دانلودش می‌کند، و چیزی برای اجرایش. Comodor از هر کدام که
پیدا کند استفاده می‌کند:

```bash
brew install llama.cpp          # macOS
winget install llama.cpp        # Windows
                                # Linux: github.com/ggml-org/llama.cpp
```

Ollama یا LM Studio، اگر هر کدام از پیش در حال اجرا باشند، هم کار می‌کنند.
`comodor local
list` وقتی هیچ چیز در دسترس نیست، به‌روشنی می‌گوید، تا پیش از هزینه کردن یک ساعت
برای دانلود باخبر شوید، نه پس از آن.

## دانلود

یک مدل، یک تا نه گیگابایت روی خط اینترنت خانه‌ی شماست، و همه چیز درباره‌ی این
دانلود با همان شکل می‌گیرد.

**از سر گرفته می‌شود.** بایت‌ها به یک فایل `.part` می‌روند. متوقفش کنید، لپ‌تاپ
را ببندید، اتصال را از دست بدهید — `comodor local get` بعدی از سرور می‌خواهد از
جایی که آن فایل تمام می‌شود ادامه دهد. مرورگر به‌جای `Download` نشان می‌دهد
`Resume (37%)`.

**راستی‌آزمایی می‌شود.** هر مدخل کاتالوگ یک شمارش دقیق بایت و یک SHA-256 همراه
دارد، و فایل تا وقتی مطابقت نکند پذیرفته نمی‌شود. این کمربند و بندِ اضافه نیست:
یک GGUF نیم‌بخته *بدیهی نیست* خراب به نظر برسد — بارگذاری می‌شود، و سپس مدل
عباراتی بی‌معنی می‌دهد، و شما یک عصر می‌گذرانید و شگفت‌زده می‌شوید چرا مدلی
خوش‌نام بی‌فایده است. فایلی که رد می‌شود حذف می‌شود، نه اینکه بماند تا بعداً
پیدا شود و نیمه‌باور شود.

**قابل تماشا است.** در ترمینال، نوارِ با چهار عددی که به پرسشی که پرسیده می‌شود
پاسخ می‌دهند:

```
qwen2.5-coder-7b-q4 ━━━━━━━━━━━━━━╸────────  38.2%  1.7/4.4 GB  8.9 MB/s  0:05:12
```

در مرورگر، همان اعداد زیر نوار روی کارت مدل، به‌روزرسانی‌شونده از جریان رویداد
نه با پول زدن.

## فایل‌ها به کجا می‌روند

یک دایرکتوری، مشترک میان هر پروژه روی ماشین — وگرنه همان مدل در سه checkout
بود، سه نسخه از همان بایت‌ها.

```bash
comodor local where
```

`comodor local remove <id>` یکی را حذف می‌کند، و می‌گوید چقدر برگشت.

## افزودن مدلی به فهرست

فهرست یک فایل JSON است، پس یک مدل تازه یک ویرایش است، نه یک انتشار. هم ترمینال
و هم مرورگر آن را برمی‌دارند.

```json
{
  "id": "my-model-q4",
  "name": "My Model 7B",
  "description": "One sentence on what it is good at, and what it is not.",
  "url": "https://huggingface.co/OWNER/REPO/resolve/main/file.gguf",
  "size": 4683074336,
  "sha256": "1664fccab734674a...",
  "context": 32768,
  "parameters": "7B",
  "quantization": "Q4_K_M",
  "needs_ram_gb": 8,
  "license": "apache-2.0",
  "good_at": ["code"],
  "tools": true,
  "vision": false
}
```

`id`، `name`، `url` و `size` الزامی‌اند — هر چیز دیگر اختیاری است، و هر چیزی که
کنار بگذارید «ناشناخته» گزارش می‌شود، نه حدس زده. یک عدد غلط اینجا بهای کسی
می‌ارزد: یک دانلود و یک کرش.

اندازه و چک‌سام را از API بگیرید، نه تایپ کردن:

```bash
curl -s 'https://huggingface.co/api/models/OWNER/REPO?blobs=true' | python -c \
  "import json,sys;[print(f['rfilename'], f['size'], f.get('lfs',{}).get('sha256')) \
   for f in json.load(sys.stdin)['siblings'] if f['rfilename'].endswith('.gguf')]"
```

دو قاعده که بارگذار اعمال می‌کند:

- **تنها `https`.** یک فایل مدل از هر جهت مهمی یک مصنوع اجرایی است، و چیزی که
  از کانالی گرفته شود که کسی می‌تواند در میانه‌ی راه بازنویسیش کند، چیزی نیست
  که به‌خاطر درخواست یک کاتالوگ مجازش کرد.
- **یک مدخل بد بهای فهرست نمی‌شود.** مدلی بدشکل رد می‌شود و بقیه بارگذاری
  می‌شوند، چون گزینه‌ی دیگر یک انتخاب‌گر خالی است.

Comodor یک نسخه از فهرست را همراه می‌فرستد و یک بار در روز نسخه‌ی تازه‌تری را
می‌کاود، و آنچه پیدا می‌کند را کش می‌کند. بی‌شبکه از کش استفاده می‌کند، و اگر
آن هم نبود، از نسخه‌ای که همراه فرستاده شده — که هدفِ اصلی فرستادنش همین است.

## آنچه انجام نمی‌دهد

`needs_ram_gb` پیش از آغاز دانلود با ماشین شما سنجیده می‌شود، و مدلی که جا
نمی‌شود همین را می‌گوید، به‌جای آنکه بگذارد یک ساعت گذرانید و بعد بفهمید.
`comodor local get --yes` اگر مخالفید آن را دور می‌زند.

دیسک هم به همان شکل بررسی می‌شود، با یک‌دهمِ باقی‌گذاشته: دانلودی که آخرین بایت
دیسک را پر کند نه فقط شکست می‌خورد، بلکه بقیه‌ی ماشین را هم با خودش می‌کشد.
