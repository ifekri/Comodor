# از Slack

همان ایجنت، در فضای کاری شما: برایش کار بفرستید، کار کردنش را ببینید، به
پرسش‌هایش پاسخ دهید — بدون باز کردن ترمینال.

```bash
comodor slack manifest              # the app definition to paste into Slack
comodor slack connect               # the two tokens, checked as you paste them
comodor slack pair                  # add your account
comodor slack start --background    # run it
```

حدود پنج دقیقه، و **هیچ نشانی عمومی‌ای برای ترتیب دادن نیست** — همان چیزی که
این را از [WhatsApp](whatsapp.md) جدا می‌کند.

همان نشست ایجنتی را اجرا می‌کند که ترمینال، مرورگر و ربات Telegram اجرا می‌کنند.
کاری که اینجا آغاز شود همان درس‌ها را می‌آموزد و در همان تاریخچه فرود می‌آید.

## چرا این آسان است

Slack دو راه برای تحویل رویدادها دارد. Events API به یک URL ارسال می‌کند، یعنی
یک نشانی عمومی HTTPS، یک گواهی و یک تونل — تمام کاری که WhatsApp را سخت
می‌کند.

**Socket Mode** آن را وارونه می‌کند: اپ از Slack نشانی websocket می‌پرسد و به
*بیرون* وصل می‌شود. هیچ چیز لازم نیست از اینترنت در دسترس باشد، و نشانی‌ای
نیست که باید به‌روز نگه داشته شود. تمام حقه همین است، و دلیلش این است که Slack
کنار Telegram می‌نشیند نه کنار WhatsApp.

چیز دوم که کمک می‌کند **مانیفست اپ** است. Slack اجازه می‌دهد یک اپ در یک سند
YAML توصیف شود، پس به‌جای یافتن یازده چک‌باکس میان چهار صفحه‌ی تنظیمات، کل اپ —
نام، دامنه‌ها، رویدادها، Socket Mode که از پیش روشن است — یک چسباندن است.

## راه‌اندازی

### ۱. ساخت اپ

```bash
comodor slack manifest
```

مانیفست و پیوند را چاپ می‌کند. در
[api.slack.com/apps](https://api.slack.com/apps?new_app=1)، گزینه‌ی **From a
manifest** را بزنید، فضای کاری‌تان را انتخاب کنید، بچسبانید، بسازید — سپس
**Install to Workspace**.

### ۲. دو توکن

جایگزین هم نیستند، و قاطی کردن‌شان تنها رایج‌ترین راه شکست همین است. Comodor هر
یک را در جای دیگری، به اسم، رد می‌کند، به‌جای آنکه بگذارد یک ساعت بعد Slack
بگوید `invalid_auth`.

| | | |
|---|---|---|
| `xoxb-…` | **توکن ربات** | OAuth & Permissions. هر کاری که ربات می‌کند را می‌کند |
| `xapp-…` | **توکن سطح اپ** | Basic Information → App-Level Tokens، دامنه‌ی `connections:write`. سوکت را باز می‌کند، و هیچ چیز دیگر |

```bash
comodor slack connect
```

بدون آرگومان هر دو را با شما طی می‌کند و هر یک را همان‌طور که می‌رسد بررسی
می‌کند — توکن ربات را با `auth.test`، توکن اپ را با واقعاً باز کردن یک سوکت با
آن. یک مورد اشتباه همین حالا یک جمله است، نه یک معمای هفته‌ی بعد.

### ۳. جفت کردن حساب شما

```bash
comodor slack pair
```

یک کد شش‌رقمی چاپ می‌کند. آن را به‌صورت پیام مستقیم به Comodor بفرستید و حساب
شما اضافه می‌شود. کد یک‌بار کار می‌کند و در پنج دقیقه منقضی می‌شود.

**یک فضای کاری می‌تواند صدها نفر درونش داشته باشد**، و این ایجنتی است که
فایل‌های شما را می‌خواند و می‌نویسد. پس تنها به یک فهرست ثابت از شناسه‌های کاربر
Slack پاسخ می‌دهد و بقیه را نادیده می‌گیرد.

```bash
comodor slack status
comodor slack forget U01234567
comodor slack forget all
```

## کجا پاسخ می‌دهد

**در پیام مستقیم**، همیشه.

**در یک کانال، تنها وقتی اشاره شده باشد.** رباتی که به هر پیام یک کانال مشترک
پاسخ می‌دهد، رباتی است که کسی همان بعدازظهر حذفش می‌کند.

**در همان رشته‌ای که با آن حرف زده شده.** پرسشی که در یک رشته پرسیده شده در همان
رشته پاسخ می‌گیرد، نه در کانال، جلوی چشم همه.

به پیام‌های خودش هرگز پاسخ نمی‌دهد — رباتی که به خودش پاسخ می‌دهد یک حلقه است با
سقف نرخ رویش.

## چه می‌تواند بکند، و چه نمی‌تواند

**به‌طور پیش‌فرض می‌خواند و برنامه می‌ریزد، و چیزی تغییر نمی‌دهد.** یک نشست
Slack فارغ از تنظیم ترمینال، در حالت plan نگه داشته می‌شود، به همان دلیلِ بقیه‌ی
کانال‌ها: تأیید یک فرمان پوسته از گوشی، در صف، تصمیمی است که با توجهی کمتر از
همان تأیید روی صفحه‌کلید گرفته می‌شود.

```bash
comodor slack writes on
comodor slack writes off
```

از عمد یک فرمان ترمینال است. رباتی که می‌توانست مجوزهای خودش را گسترش دهد تنها
به حساب Slack یک نفر نیاز داشت.

## دکمه‌ها

Slack جادارترینِ سه کانال است — پیام‌ها ویرایش‌شدنی‌اند و دکمه‌ها فراوان — پس
پاسخ یک پیام است که با رسیدن جواب بزرگ می‌شود، و کل منو در یک صفحه جا می‌شود.

| | |
|---|---|
| **چت جدید** | فراموش کردن گفتگوی تاکنونی |
| **تاریخچه** | بازگشایی یک گفتگوی پیشین |
| **حالت** | عمل، برنامه یا چت |
| **وضعیت** | مدل، پوشه، زمینه، خرج |
| **مدل** | تغییر به مدل دیگر |
| **پوشه** | در کدام پروژه کار می‌کند |
| **مهارت‌ها** | نصب یا حذف یکی |
| **قواعد** | چه آموخته از اصلاحات شما |
| **چه کاری مجاز است** | آیا می‌تواند ویرایش و اجرا کند |
| **راهنما** | هر چیز چه می‌کند |

وقتی کاری در حال اجراست تنها چیزی که پیشنهاد می‌شود **توقف** است.

## اجرایش

```bash
comodor slack start                # here, holding this terminal
comodor slack start --background   # detached; survives closing it
comodor slack stop
comodor slack service install      # starts at login, survives a reboot
comodor slack service show         # read the unit before trusting it
```

گزارش `slack.log` کنار پیکربندی شماست، به آن اضافه می‌شود نه اینکه جایگزین شود.

روی هر پلتفرم یک سرویس **کاربری** — systemd، launchd، Task Scheduler — هرگز یک
سرویس سیستمی. این ایجنتی است که با اعتبارنامه‌های شما فایل‌هایتان را می‌خواند و
می‌نویسد، و اختیارِ بیشتر از شخصی که مالک آن فایل‌هاست هیچ چیز نمی‌خرد.

## از پنل مرورگر

`comodor web` → **Admin** → **از گوشی شما** همه‌ی این‌ها را — اتصال، جفت کردن،
اجرا و توقف — بدون ترمینال انجام می‌دهد. آن کنترل‌ها تنها به درخواست‌های آمده از
ماشینی پاسخ می‌دهند که Comodor روی آن اجراست: توکن ربات کنترل از راه دور آن را
به هر دارنده‌ی توکن می‌دهد.

## چگونه ساخته شده

بدون وابستگی تازه. Web API یک `POST /api/chat.postMessage` روی کلاینت HTTP‌ای
است که این پروژه از پیش دارد، و Socket Mode روی کلاینت websocket‌ای اجرا
می‌شود که برای راندن Chrome نوشته شده — دلیل اینکه افزودن Slack هیچ بسته‌ای
افزود.

سه چیز که حلقه‌ی سوکت درباره‌شان مواظب است، و هر یک راهی است که یک ربات بی‌سروصدا
خاموش می‌شود بی‌آنکه کسی بفهمد:

- **هر پاکت رسیدهاش می‌شود.** Slack هر چیزی که درباره‌اش نشنود دوباره تحویل
  می‌دهد، و برای ایجنتی که فرمان اجرا می‌کند، تبدیل یک پیام به سه نوبت تنها
  پرسر و صدا بودن نیست.
- **`disconnect` عادی است.** Slack اتصال‌ها را طبق زمان‌بندی می‌چرخاند. رفتار
  کردن با آن به‌عنوان شکست، رباتی می‌سازد که هر چند ساعت می‌میرد.
- **یک فضای کاری ساکت همچنان پینگ می‌گیرد.** حالتی که بیش از همه اهمیت دارد —
  یک ساعت است کسی به آن پیام نداده — دقیقاً همان حالتی است که افتادن سوکت
  خرابش می‌کند.

## آنچه انجام نمی‌دهد

- پاسخ دادن به هر کسی که جفت نشده.
- پاسخ دادن به همه چیز در کانالی که به آن اضافه شده.
- گرفتن توکن یا حسابی مجاز از `.comodor/config.json` یک پروژه. مخزنی که بتواند
  نویسنده‌اش را به آن فهرست اضافه کند یک درِ پشتی می‌شد.
- ویرایش هیچ چیز تا وقتی `slack writes on` نشده.
- چاپ هیچ‌کدام از دو توکن. هر دو از هر خطایی که برانگیخته می‌شود پیراسته شده‌اند.
