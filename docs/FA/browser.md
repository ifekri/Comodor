# مرورگر واقعی

یک صفحه‌گیرِ ساده نیست. مرورگری که واقعاً روی ماشین نصب شده — جاوااسکریپت را اجرا
می‌کند، کوکی‌ها را نگه می‌دارد و می‌تواند وارد سیستم شود.

---

## از چه چیزی استفاده می‌کند

Chrome، Chromium، Edge یا Brave — هر کدام روی ماشین باشد. **هیچ چیزی دانلود
نمی‌شود.** یکی از آن‌ها را در یک پروفایل مخصوص به خودش اجرا می‌کند که به هیچ‌جایی
وارد نشده، و وقتی جلسه تمام شد آن را می‌بندد.

اگر هیچ‌کدام نصب نباشد، `browse` به یک مرورگر متنی برمی‌گردد که همچنان به بیشتر
پرسش‌ها درباره‌ی یک صفحه پاسخ می‌دهد. هر دو `browse` نامیده می‌شوند، چون انتخاب میان
دو چیز که هر دو «مرورگر» نام دارند، نوبتی است که مدل نباید برایش هزینه کند.

---

## چه چیزی برمی‌گردد

نه اسکرین‌شات. عنوان، متن خوانا، و **فهرست شماره‌دارِ کنترل‌هایی که واقعاً روی
صفحه هستند**:

```
  Sign in — Example
  ─────────────────────────────────────────────
  Sign in to your account. New here? Create one.

  [1]  textbox   Email
  [2]  textbox   Password
  [3]  button    Sign in
  [4]  link      Forgot your password?
```

مدل روی هر یک با شماره‌اش عمل می‌کند. آن فهرست به چیزهایی پالایه شده که مرئی،
نام‌دار، روی صفحه و بدون تکرار باشند — که بسیار کوچک‌تر از درخت دسترس‌پذیری است و،
به‌اندازه‌گیری، از اسکرین‌شات همان صفحه هم کوچک‌تر.

اسکرین‌شات فقط وقتی که پرسش دیداری است — چیدمان، ظاهر، یک نمودار — چون یک تصویر
هر بار هزینه‌ی یکسانی دارد و نمی‌توان آن را کوتاه کرد.

---

## فعل‌ها

| | |
|---|---|
| `open` | رفتن به یک URL |
| `click` | یک کنترل، با شماره‌اش |
| `type` | تایپ در یک فیلد، با شماره‌اش |
| `scroll` | به بالا یا پایین |
| `back` | صفحه‌ی پیشین |
| `read` | خواندن دوباره‌ی صفحه، پس از آنکه چیزی تغییر کرد |
| `look` | یک اسکرین‌شات، وقتی پرسش درباره‌ی ظاهر آن است |
| `script` | اجرای جاوااسکریپت و گرفتن مقدارش |

---

## دیدن کارکردش

```json
{ "browser": { "headless": false } }
```

یک پنجره‌ی مرئی، تا ببینید چه می‌کند.

> این تنظیم روزی نادیده گرفته می‌شد — `browser` به‌عنوان یک بخش پیکربندی ثبت
> نشده بود، پس هر تنظیمِ `browser` بی‌سروصدا هیچ کاری نمی‌کرد. در 0.9.0 برطرف شد.

---

## استفاده از جلسه‌ای که از پیش واردش شده‌اید

به‌جای سپردن پروفایل خودتان، مرورگر خودتان را با یک پورت DevTools راه بیندازید و
Comodor را به آن اشاره دهید:

```bash
chrome --remote-debugging-port=9222
```

```json
{ "browser": { "port": 9222 } }
```

به همان مرورگر وصل می‌شود و از زبانه‌ها و کوکی‌های از پیش موجود استفاده می‌کند.
کار که تمام شد پورت را ببندید — هر چیزی روی ماشین شما می‌تواند از آن استفاده کند.

## همه‌ی تنظیمات

```json
{
  "browser": {
    "executable": "",
    "headless": true,
    "width": 1280,
    "height": 800,
    "port": 0
  }
}
```

| | |
|---|---|
| `executable` | یک مرورگر مشخص. خالی یعنی در جای‌های همیشگی بگرد |
| `headless` | به‌طور پیش‌فرض نامرئی، تا فوکوس را نرباید |
| `width`, `height` | پنجره |
| `port` | اتصال به مرورگری که خودتان اجرا کرده‌اید، به‌جای اجرای یکی |

یک مخزن نمی‌تواند هیچ‌کدام از این‌ها را تنظیم کند — `browser.executable` نام یک
باینری است که باید اجرا شود. [ایمنی](safety.md#what-a-repository-may-set).

---

## `browse` یا `web_fetch`؟

| | |
|---|---|
| `web_fetch` | صفحه یک سند است. آن را به متن تبدیل می‌کند. ارزان |
| `browse` | صفحه یک اپلیکیشن است. به جاوااسکریپت، ورود یا یک کلیک نیاز دارد |

به مدل گفته می‌شود که `web_fetch` را ترجیح دهد و وقتی کفایت نکرد سراغ `browse`
برود.

## درون یک کانتینر

ایمیج Docker هم Chromium را همراه دارد و هم فونت‌های لازم برای رندر با آن. سندباکس
خود Chromium نمی‌تواند درون کانتینری که پروفایل seccomp آن فضاهای نام کاربر را
مسدود می‌کند اجرا شود، پس Comodor آن را تشخیص می‌دهد و بدون سندباکس داخلی دوباره
تلاش می‌کند — با حفظ محصورسازی خود کانتینر، که مرز واقعی همان است. [Docker](docker.md).

## زیر سرپوش

پروتکل Chrome DevTools روی یک WebSocket دست‌ساز. بدون وابستگی: کادربندی RFC 6455
حدود صد خط است و بخشی از خود بسته است، همان‌طور که کلاینت HTTP و خواننده‌ی SSE
هستند.
