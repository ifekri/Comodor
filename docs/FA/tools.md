# کارهایی که عامل می‌تواند بکند

سیزده ابزار. هر کدام سطح ریسکی را اعلان می‌کند که مشخص می‌کند آیا اول بپرسد یا
نه — به [ایمنی](safety.md#risk-tiers) نگاه کنید.

---

## فایل‌ها

| | ریسک | |
|---|---|---|
| `read_file` | safe | خواندن یک فایل متنی. به صورت جریان، پس تکه‌ای از یک لاگ بزرگ هم در دسترس است |
| `list_dir` | safe | مدخل‌های یک پوشه، با اندازه‌ها |
| `glob` | safe | یافتن فایل‌ها با الگوی نام — `src/**/*.py` |
| `grep` | safe | جست‌وجوی محتوا با یک عبارت باقاعده |
| `write_file` | write | ساختن یک فایل یا جایگزینی کاملش |
| `edit_file` | write | جایگزینی یک رشتهٔ دقیق در یک فایل |

همه‌چیز به پوشهٔ پروژه محدود است مگر اینکه `safety.workspace_only` را خاموش
کنید.

`edit_file` برای تغییری در یک فایل موجود به `write_file` ترجیح داده می‌شود:
کوچک‌تر است، به شکل یک diff قابل بازبینی است، و نمی‌تواند بی‌سروصدا بقیهٔ
فایل را از دست بدهد.

---

## اجرا کردن چیزها

| | ریسک | |
|---|---|---|
| `run_shell` | dangerous | یک فرمان شل در فضای کاری |
| `run_python` | dangerous | تکه‌ای کوتاه پایتون، در یک فرایند فرعی |

هر دو قبل از اجرا می‌پرسند، هر دو مشمول `safety.deny_commands` هستند، و خروجی
هر دو کران‌دار است — به [وقتی خروجی بیش از حد بزرگ است](#when-output-is-too-big)
نگاه کنید.

در رابط می‌توانید مدل را کاملاً دور بزنید:

```
!git status
```

آن را اجرا می‌کند، خروجی را به شما نشان می‌دهد، و هرگز آن را با مدل در
میان نمی‌گذارد. سریع‌تر و ارزان‌تر از پرسیدن.

---

## وب

| | ریسک | |
|---|---|---|
| `web_fetch` | dangerous | دانلود یک URL و برگرداندن متنِ خوانا‌شده‌اش |
| `web_search` | dangerous | جست‌وجو، و برگرداندن عنوان‌ها، URL ها و قطعه‌ها |
| `browse` | dangerous | یک مرورگر واقعی — جاوااسکریپت، کوکی‌ها، لاگین‌ها |

`web_fetch` ارزان‌ترین است: صفحه را به متن تقلیل می‌دهد. وقتی صفحه یک سند است
از آن استفاده کنید.

`browse` برای وقتی است که صفحه یک اپلیکیشن است — چیزی که به جاوااسکریپت، یک
لاگین، یا یک کلیک نیاز دارد. [راهنمای کامل](browser.md).

---

## دستگاه

| | ریسک | |
|---|---|---|
| `computer` | dangerous | موس، کیبورد و صفحه، در هر برنامه‌ای |

خاموش است مگر اینکه خودتان روشنش کنید، و بعدش هم تا وقتی اجازه داده نشود مجاز
نیست. [راهنمای کامل](computer.md). فعلاً فقط ویندوز.

## کنار هم نگه داشتن حساب

| | ریسک | |
|---|---|---|
| `todo_write` | safe | فهرست وظایفی که در نوار کناری می‌بینید |

عامل برنامهٔ خودش را همین‌جا می‌نویسد. تزئین نیست — همان چیزی است که یک وظیفهٔ
طولانی منسجم می‌ماند، و همان چیزی که به شما می‌گوید کجای کار است.

---

## گاهی هست، گاهی نیست

کامودور فقط ابزاری را پیشنهاد می‌دهد که مدل واقعاً بتواند از آن استفاده کند.
ابزاری که مدل ببیند ولی هرگز نتواند با موفقیت از آن استفاده کند، در هر نوبت یک
فراخوان هدر رفته دعوت می‌کند.

| | چه وقت ظاهر می‌شود |
|---|---|
| `read_skill_file` | یک مهارت نصب‌شدهٔ شما فایل‌هایی به همراه داشته باشد |
| `search_history` | نشست‌هایی از گذشته برای جست‌وجو باشد |
| `delegate` | بتوان یک زیرعامل راه انداخت |
| `computer` | پلتفرم یک backend داشته باشد **و** شما آن را فعال کرده باشید |
| ابزارهای MCP | یک سرور پیکربندی و فعال شده باشد |

`browse` دو پیاده‌سازی دارد: مرورگر واقعی وقتی Chrome، Chromium، Edge یا Brave
نصب باشد، و یک مرورگر متنی وقتی هیچ‌کدام نیست. هر دو `browse` نام دارند، چون
انتخاب میان دو چیز به نام «browser» یک نوبت است که مدل نباید برایش مصرف شود.

## وقتی خروجی بیش از حد بزرگ است

فرمانی که پنجاه هزار خط چاپ می‌کند، نه بی‌معنی و بی‌فایده بریده می‌شود و نه
زمینهٔ (context) گفت‌وگو را منفجر می‌کند.

هر چه جا شود به مدل می‌رود — سر و ته، چون جواب معمولاً همان‌جاست. بقیه در
فایلی زیر `~/.comodor/output/` نوشته می‌شود، و به مدل مسیر و شیوهٔ خواندنش
گفته می‌شود. پس اگر لازم داشت می‌رود نگاه می‌کند، و اگر لازم نداشت هیچ هزینه‌ای
نمی‌دهد.

```json
{ "agent": { "max_tool_chars": 12000 } }
```

## زیرعامل‌ها

`delegate` یک عامل دوم را در یک **git worktree** اجرا می‌کند — یک checkout
ایزوله از همان مخزن. آنجا کار می‌کند، و تغییراتش به شکل یک وصله برمی‌گردند که
با ادغام سه‌طرفه اعمال می‌شود.

حافظه‌ای ندارد، نمی‌تواند باز هم delegate کند، و صفحه به او داده نمی‌شود. لغو
والد را به ارث می‌برد، پس `Esc` آن را هم می‌ایستاند.

برای کاری که واقعاً جداست مفید است — «این ماژول را به API جدید ببر، من سر کارم»
— و برای هر چیز دیگری هدر دادن است.

## ابزارهای MCP

هر چیزی که یک سرور Model Context Protocol فعال فراهم کند، در کنار ابزارهای
داخلی ظاهر می‌شود و از دقیقاً همان دروازهٔ مجوز می‌گذرد.

```bash
comodor mcp list
```

[راهنمای کامل](mcp.md).
