# از گوشی شما

Comodor می‌تواند از طریق یک ربات Telegram به حرکت درآید: برایش کار بفرستید، کار
کردنش را ببینید، به پرسش‌هایش پاسخ دهید و متوقفش کنید — بدون باز کردن ترمینال.

**راه‌اندازی نخستین اجرا از این می‌پرسد.** واپسین پرسش از میان شش پرسش، پیشنهاد
اتصال یک ربات می‌دهد، توکن را همان لحظه با Telegram بررسی می‌کند، و پیش از
پایان یافتن جادوگر حساب شما را جفت می‌کند. اگر گفته‌اید *Not now*، یا ماشینی را
راه‌اندازی می‌کنید که از قبل پیکربندی شده:

```bash
comodor telegram connect <token>   # a bot from @BotFather
comodor telegram pair              # add your account
comodor telegram start             # run it
```

همان نشست ایجنتی را اجرا می‌کند که رابط مرورگری اجرا می‌کند. همه چیز یک دکمه
است؛ تایپ برای خودِ کار است.

## گرفتن یک ربات

به [@BotFather](https://t.me/botfather) در Telegram پیام بدهید، `/newbot` را
بفرستید، برایش نامی و نام کاربری‌ای که به `bot` ختم شود انتخاب کنید. با یک توکن
پاسخ می‌دهد:

```
1234567890:AAF…
```

```bash
comodor telegram connect 1234567890:AAF…
```

## جفت کردن

**نام کاربری یک ربات عمومی است.** هر کسی که پیدایش کند می‌تواند به آن پیام
بدهد، و این یکی می‌تواند فایل‌های شما را بخواند. پس تنها به یک فهرست ثابت از
شناسه‌های عددی کاربر Telegram پاسخ می‌دهد و به هیچ‌کس دیگر.

```bash
comodor telegram pair
```

یک کد شش‌رقمی چاپ می‌کند. آن را در Telegram به ربات خودتان بفرستید و حساب شما
اضافه می‌شود. کد یک‌بار کار می‌کند و در پنج دقیقه منقضی می‌شود.

بقیه همه **سکوت** می‌گیرند — نه یک رد. رباتی که می‌گوید «شما مجاز نیستید»، به
یک غریبه گفته که وجود دارد، که یک Comodor است، و که فهرستی هست که ارزش رسیدن به
آن را دارد.

```bash
comodor telegram status         # who may talk to it
comodor telegram forget 12345   # revoke one account
comodor telegram forget all     # revoke everybody
```

## چه می‌تواند بکند، و چه نمی‌تواند

**به‌طور پیش‌فرض می‌خواند و برنامه می‌ریزد، و چیزی تغییر نمی‌دهد.** یک نشست
Telegram فارغ از اینکه ترمینال چه تنظیمی دارد، در حالت plan نگه داشته می‌شود.

این از روی عمد است. تأیید یک فرمان پوسته با شست، روی گوشی، در صف، تصمیمی است
که با توجهی کمتر از همان تأیید روی صفحه‌کلید گرفته می‌شود — و پیامدها یکسانند.

```bash
comodor telegram writes on      # let it edit files and run commands
comodor telegram writes off
```

با روشن بودن نوشتن‌ها باز هم نخست می‌پرسد، و تأیید یک دکمه در همان چت است:

```
Comodor wants to run
  npm test

  ✓  Yes, once
  ✓✓ Yes, and stop asking this session
  ✗  No
```

گسترده‌ترین تعهد هرگز نخستین دکمه زیر شست شما نیست — روی گوشی نزدیک به هم
هستند و «همیشه» قابل بازگشت نیست.

## دکمه‌ها

`/start` با مدل، پوشه و آنچه مجاز است بکند پاسخ می‌دهد، و تنظیمات زیر آن. روی
صفحه‌ی نخست هستند، نه پشت دکمه‌ی *Settings*، چون اینکه یک ربات به چه چیزی
اشاره شده نخستین چیزی است که هر کسی می‌خواهد بداند و نخستین چیزی که می‌خواهد
عوض کند.

| | |
|---|---|
| **چت جدید** | فراموش کردن گفتگوی تاکنونی |
| **تاریخچه** | بازگشایی هر گفتگوی پیشین، به‌طور کامل |
| **توقف** | قطع آنچه در حال اجراست — در حین اجرا جای *چت جدید* را می‌گیرد |
| **حالت** | عمل، برنامه یا چت، هر یک به‌روشنی نوشته شده |
| **وضعیت** | مدل، پوشه، زمینه، خرج |
| **مدل** | هر مدلی که ارائه‌دهنده می‌دهد؛ با ضربه عوضش کنید |
| **پوشه** | به کدام پروژه محدود است |
| **مهارت‌ها** | نصب یا حذف یکی از کتابخانه |
| **قواعد** | چه آموخته از اصلاحات شما، و چند تا |
| **تنظیمات** | بقیه — هزینه، و چه کاری می‌تواند بکند |
| **راهنما** | هر چیز چه می‌کند، بدون ترک چت |

وقتی ایجنت به یک تصمیم نیاز پیدا کند، با دکمه هم می‌پرسد — همان پرسش‌هایی که در
ترمینال می‌پرسید، یکی در هر صفحه، با **Write my own** برای هر چیزی که به ذهنش
نرسیده بود.

فهرست‌های بلندتر از یک صفحه — مدل‌ها، مهارت‌ها، تاریخچه — شش‌تا شش‌تا صفحه‌بندی
می‌شوند، با **Previous** و **Next**. Telegram هشتاد دکمه را با کمال میل ترسیم
می‌کند و هیچ‌کس آن‌ها را اسکرول نخواهد کرد.

## اجرایش

سه راه، به ترتیب اینکه چقدر می‌خواهید دوام بیاورد.

```bash
comodor telegram start                # here, holding this terminal
comodor telegram start --background   # detached; survives closing the terminal
comodor telegram service install      # starts at every login, survives a reboot
```

**در پیش‌زمینه** ترمینال را در اختیار دارد و نشان می‌دهد چه می‌کند. این همان
گزینه‌ای است که حین راه‌اندازی استفاده کنید، و همان است که وقتی چیزی کار نمی‌کند
به سراغش برگردید.

**در پس‌زمینه** همان فرآیند است، جدا از ترمینالی که آن را آغاز کرده، به‌جای
صفحه در یک گزارش می‌نویسد. بستن ترمینال، خروج، پایان دادن به نشست — هیچ‌کدام
آن را با خود نمی‌برند.

```bash
comodor telegram stop        # end it
comodor telegram status      # is it running, since when, and as which pid
```

گزارش `telegram.log` کنار پیکربندی شماست، و به آن اضافه می‌شود نه اینکه جایگزین
شود — دلیلِ توقف یک ربات دیشب در همان خط‌هاست که یک ری‌استارت در غیر این صورت
پاک می‌کرد.

**در ورود** کارِ سیستم‌عامل است، نه ما: هیچ چیزِ آنچه یک برنامه برای خودش آغاز
کند، از ری‌استارت شدن ماشین جان به در نمی‌برد.

```bash
comodor telegram service show        # read the unit before trusting it
comodor telegram service install
comodor telegram service uninstall
```

| | |
|---|---|
| Linux | یک یونیت **کاربری** systemd در `~/.config/systemd/user` |
| macOS | یک LaunchAgent در `~/Library/LaunchAgents` |
| Windows | یک تسک Task Scheduler که هنگام ورود اجرا می‌شود |

روی هر سه یک سرویس کاربری، هرگز یک سرویس سیستمی. یک سرویس سیستمی با root یا
SYSTEM اجرا می‌شود، و این ایجنتی است که با اعتبارنامه‌های شما فایل‌هایتان را
می‌خواند و می‌نویسد — اختیارِ بیشتر از شخصی که مالک آن فایل‌هاست، هیچ چیز
نمی‌خرد و اگر روزی اشتباه باشد همه چیز را خرج می‌کند.

`service show` یونیت را پیش از آنکه `service install` بنویسدش چاپ می‌کند.
هیچ‌کس نباید از او بخواهند به تعریف یک دیمن اعتماد کند که نشانش نداشته است.

پوشه در هر سه اهمیت دارد: ایجنت تنها درون دایرکتوری‌ای می‌خواند و می‌نویسد که
در آن اجرا شده، و آن همان است که ربات در آن کار خواهد کرد.

## چگونه ساخته شده

بدون وابستگی تازه. Bot API یک حلقه‌ی `getUpdates` و یک `sendMessage` است، روی
کلاینت HTTP‌ای که این پروژه از پیش دارد — `python-telegram-bot` بزرگ‌ترین چیزی
می‌شد که در چرخ حمل می‌شد، برای همین.

پاسخ با یک تایمر ویرایش می‌شود، نه به‌ازای هر توکن. Telegram به‌ازای هر ویرایش
یک رفت‌وبرگشت خرج می‌کند و بر آن‌ها سقف نرخ می‌گذارد، پس ویرایش به‌ازای هر توکن
پیامی می‌سازد که تنگنا گرفته و یکجا در پایان می‌رسد.

ربات یک آفست به‌روزرسانی نگه می‌دارد و با پیشرفتش جلو می‌برد. بدون آن، یک
ری‌استارت تک‌تک پیام‌هایی را که ربات تاکنون گرفته بازپخش می‌کند — که برای ایجنتی
که فرمان اجرا می‌کند، تنها پرسر و صدا بودن نیست.

## آنچه انجام نمی‌دهد

- پاسخ دادن به هر کسی که جفت نشده، یا گفتن اینکه چرا.
- گرفتن توکن یا حسابی مجاز از `.comodor/config.json` یک پروژه. مخزنی که بتواند
  نویسنده‌اش را به آن فهرست اضافه کند یک درِ پشتی می‌شد، و برخلاف مرورگر یا
  صفحه‌نمایش هیچ چیزِ روی صفحه‌ای نبود که در حال رخ دادنش را ببینید.
- ویرایش هیچ چیز تا وقتی `telegram writes on` نشده.
- چاپ توکن. در هر URL از Bot API هست، پس هر خطایی که برانگیخته می‌شود آن از آن
  پیراسته شده است.
