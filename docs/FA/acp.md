# درون ویرایشگر شما

Comodor با [پروتکل Agent Client](https://agentclientprotocol.com) صحبت می‌کند، بنابراین
ویرایشگری که از آن پشتیبانی کند می‌تواند Comodor را مستقیماً به حرکت درآورد — با پنل خودش،
پیام‌های اجازه‌ی خودش و نمای فایل خودش — با همان ایجنت، همان قواعد آموخته‌شده و همان
گزارش‌های گفتگو که در ترمینال می‌بینید.

```bash
comodor acp
```

معمولاً لازم نیست این را خودتان تایپ کنید. ویرایشگر آن را اجرا می‌کند.

---

## راه‌اندازی

Comodor بلوکی را که ویرایشگر شما درخواست می‌کند چاپ می‌کند:

```bash
comodor acp --print-config
```

```json
{
  "agent_servers": {
    "Comodor": {
      "command": "/home/you/.local/bin/comodor",
      "args": ["acp"],
      "env": {}
    }
  }
}
```

این بلوک کجا قرار می‌گیرد به ویرایشگر بستگی دارد. سه ویرایشگری که هنگام نوشتن این
متن روی یک ماشین واقعی راه‌اندازی و بررسی شدند:

**JetBrains** — PyCharm، IntelliJ، WebStorm و بقیه، از طریق افزونه‌ی AI
Assistant. بلوک را در `~/.jetbrains/acp.json` قرار دهید، یا از گزینه‌ی *Add Custom
Agent* در منوی پنجره‌ی AI Chat استفاده کنید که همان فایل را باز می‌کند. سپس Comodor
در انتخاب‌گر ایجنت، پایین پنل چت، ظاهر می‌شود. برای این کار به اشتراک JetBrains AI
نیازی نیست — ایجنت‌های ACP بدون آن هم کار می‌کنند.

**VS Code** — یک افزونه‌ی کلاینت ACP نصب کنید؛ [ACP
Client](https://marketplace.visualstudio.com/items?itemName=formulahendry.acp-client)
همانی است که این متن با آن بررسی شد. بلوک زیر کلید `acp.agents` در
`settings.json` قرار می‌گیرد و Comodor در فهرست ایجنت‌های پنل ACP ظاهر می‌شود.

**Zed** — در `settings.json`، و Comodor در پنل ایجنت ظاهر می‌شود.

گزارش شده که در این‌ها هم کار می‌کند، هرچند اینجا بررسی نشده: Neovim (CodeCompanion,
avante.nvim, agentic.nvim)، Emacs (agent-shell.el)، Qt Creator، Obsidian و
Visual Studio.

پروتکل همه‌جا یکی است؛ تنها فایل تنظیمات فرق می‌کند.

اول Comodor را در ترمینال راه‌اندازی کنید:

```bash
comodor setup
```

ویرایشگر جایی ندارد که بپرسد از کدام ارائه‌دهنده استفاده کند، پس Comodori که هرگز
پیکربندی نشده از شروع یک جلسه خودداری می‌کند و می‌گوید کدام فرمان را اجرا کنید. این
پیامی روشن درون ویرایشگر است، نه شکستی در نخستین کار.

## آنچه ویرایشگر به دست می‌آورد

| | |
|---|---|
| پاسخ‌های جریانی | همان‌طور که مدل می‌نویسد |
| فراخوانی ابزارها | هر یک با نام خودش، همراه با کاری که انجام داد، و نشانه‌گذاری‌شده به‌صورت خواندن / ویرایش / اجرا تا ویرایشگر بتواند آیکونی برگزیند |
| پیام‌های اجازه | در ویرایشگر پرسیده می‌شوند، در ویرایشگر پاسخ داده می‌شوند |
| برنامه‌ها | وقتی Comodor فهرست کارهایی می‌نویسد، ویرایشگر آن را ترسیم می‌کند |
| لغو | دکمه‌ی توقف ویرایشگر، نوبت جاری را قطع می‌کند |
| جلسات | فهرست می‌شوند، از سر گرفته می‌شوند و حذف می‌شوند — همان گزارش‌هایی که `comodor` از سر می‌گیرد |

پوشه‌ی کاری از ویرایشگر می‌آید: هر پروژه‌ای که باز داشته باشید همان‌جایی است که
ایجنت می‌خواند و می‌نویسد، و به همان محدود است.

---

## آنچه انجام نمی‌دهد

**گرفتن ارائه‌دهنده‌ی مدل از ویرایشگر.** ارائه‌دهنده، مدل، قواعد، مهارت‌ها و
مجوزهای Comodor از آنِ خودش است و با `comodor setup` یا در رابط مرورگری
پیکربندی می‌شود. ویرایشگری که بخواهد مدلی را نیز پیکربندی کند، مرجع دومی برای
همان یک تنظیم خواهد بود.

**ورود به سیستم.** Comodor به یک ارائه‌دهنده‌ی مدل احراز هویت می‌شود، نه به
ویرایشگر شما، پس هیچ روش احراز هویتی اعلام نمی‌کند و کلاینت از شما ورود نمی‌خواهد.

---

## وقتی چیزی درست نیست

پروتکل خروجی استاندارد را برای پیام‌ها نگه داشته، بنابراین گزارش‌های Comodor به
خطای استاندارد می‌روند. ویرایشگرها معمولاً آن را جایی نشان می‌دهند — در Zed این
گزارشِ سرور ایجنت است.

```
comodor acp — speaking ACP v2 on stdio
```

یک مورد رایج که شبیه ایجنتی خراب به نظر می‌رسد، در حالی که چیزی دیگری است: امتناع
ارائه‌دهنده از کلید شما. این در ویرایشگر به‌صورت `Error during prompt
turn` می‌رسد، یا به بیان خودِ ارائه‌دهنده — برای نمونه `OpenRouter: User not found`،
یعنی کلید باطل شده است. فرمان `comodor doctor` می‌گوید کدام ارائه‌دهنده پیکربندی
شده؛ رابط مرورگری کلید تازه‌ای می‌پذیرد یا وارد سیستم‌تان می‌کند.

اگر ایجنت وصل شد و سپس کاری نکرد، نخست `comodor doctor` را در ترمینال اجرا کنید:
ارائه‌دهنده‌ای که در دسترس نیست از ویرایشگر شبیه ایجنتی خراب دیده می‌شود.
