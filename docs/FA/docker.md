# در Docker

ایجنت، مرورگرش و هر آنچه نیاز دارد، درون یک کانتینر.

```bash
git clone https://github.com/ifekri/Comodor.git
cd Comodor
export ANTHROPIC_API_KEY=…        # or OPENAI_API_KEY, OPENROUTER_API_KEY, …
docker compose up
```

نخستین بار ایميج را می‌سازد، سپس نشانی را چاپ می‌کند:

```
  Comodor is at  http://127.0.0.1:8765/?token=…
  Working in     /work
```

پیوند را باز کنید. در هر اجرا توکنی تازه، پس از اجرای *همین* اجرا استفاده کنید.

یا بدون کلون کردن هیچ چیز:

```bash
docker run --rm -it -p 127.0.0.1:8765:8765 \
  -e ANTHROPIC_API_KEY \
  -v "$PWD:/work" \
  ghcr.io/ifekri/comodor:latest
```

---

## اینجا کلید اختیاری نیست

رابط مرورگری راهی برای وارد کردنش ندارد، پس بدون کلید کانتینر می‌گوید چه چیزی
کم است و می‌ایستد، به‌جای آنکه URL‌ای سرو کند که در نخستین کار شکست می‌خورد.

Compose هر یک از این‌ها را که در پوسته‌ی شما تنظیم شده عبور می‌دهد، بدون نوشتنش
در ایميج یا فایل compose:

```
ANTHROPIC_API_KEY   OPENAI_API_KEY   OPENROUTER_API_KEY   DEEPSEEK_API_KEY
GOOGLE_API_KEY      GROQ_API_KEY     XAI_API_KEY          MISTRAL_API_KEY
XIAOMI_API_KEY
```

فایل را به تاریخچه‌ی پوسته ترجیح می‌دهید؟ آن را در یک `.env` کنار فایل compose
بگذارید — compose آن را می‌خواند، و در git نادیده گرفته می‌شود.

---

## کجا کار می‌کند

هر چیزی که ایجنت می‌تواند لمس کند، پوشه‌ی `work/` کنار فایل compose است. به
جای دیگری اشاره‌اش دهید:

```yaml
volumes:
  - "/path/to/your/project:/work"
```

آنچه یاد می‌گیرد — مغز، اصلاحات شما، گزارش‌های جلسه — در یک volume نام‌دار
زندگی می‌کند، پس از `docker compose down` جان به در می‌برد و با
`docker compose down -v` فراموش می‌شود.

---

## چه کسی می‌تواند به آن برسد

```yaml
ports:
  - "127.0.0.1:8765:8765"
```

**آن `127.0.0.1` سمت چپ، تمام مدل امنیتی است.** برداریدش و پورت روی تک‌تک
رابط‌های ماشین است — و این پورت یک پوسته است.

درون کانتینر، Comodor روی `0.0.0.0` بایند می‌شود، که این یک غفلت نیست: کانتینر
فضای نام شبکه‌ی خودش را دارد، پس بایند به loopback درون یک کانتینر، پورت را از
ماشینی که آن را اجرا می‌کند پنهان می‌کند. اینکه چه کسی واقعاً می‌تواند برسد را
شیوه‌ی انتشار پورت تعیین می‌کند، و بنر همین را می‌گوید.

---

## کانتینر چه کاری مجاز است بکند

```yaml
cap_drop: [ALL]
security_opt:
  - no-new-privileges:true
```

فرمان‌های پوسته اجرا می‌کند، پس خود کانتینر همان است که میان آن‌ها و ماشین شما
می‌ایستد. هیچ چیزِ آنچه لازم ندارد به او داده نمی‌شود، و به‌عنوان کاربری غیر root
اجرا می‌شود.

---

## پین کردن یک نسخه

```yaml
args:
  COMODOR_VERSION: ""
```

به‌طور پیش‌فرض پین شده تا بازساخت تکرارپذیر باشد. برای تازه‌ترین انتشار:

```bash
docker compose build --build-arg COMODOR_VERSION=
```

---

## اجرای چیز دیگری درونش

```bash
docker compose run --rm comodor comodor doctor
docker compose run --rm comodor sh
```

بدون آرگومان، یا با آرگومان‌هایی که با خط تیره شروع می‌شوند، یعنی «رابط وب را با
این گزینه‌ها اجرا کن». هر چیز دیگر، فرمانی است که به‌جای آن اجرا می‌شود.

---

## آنچه در کانتینر نیست

**صفحه‌نمایش شما.** [کنترل دسکتاپ](computer.md) ماشینی را می‌رانَد که Comodor
روی آن اجراست، و درون یک کانتینر آن ماشینی است بدون نمایشگر. ابزار آنجا پیشنهاد
نمی‌شود.

[مرورگر](browser.md) کار می‌کند — Chromium و فونت‌هایش در ایميج هستند.

---

## اگر اجرا نمی‌شود

**هیچ چیز در `localhost:8765`** — بررسی کنید پورت منتشر شده باشد:
`docker compose ps`.

**فوراً خارج می‌شود** — گزارش را بخوانید. تقریباً همیشه هیچ ارائه‌دهنده‌ای
پیکربندی نشده؛ پیام می‌گوید چه چیزی را تنظیم کنید.

**`exec /usr/local/bin/comodor-start: no such file or directory`** — یک checkout
با CRLF. در شاخه با یک `.gitattributes` برطرف شده؛ اگر می‌بینیدش، pull بزنید.
