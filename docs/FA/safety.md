# ایمنی و مجوزها

کامودور چه کاری با دستگاه شما می‌تواند بکند، اول دربارهٔ چه چیزی می‌پرسد، و چه
چیزی را هر چه بگویید نخواهد کرد.

---

## نسخهٔ کوتاه

- **خواندن بی‌صدا است.** فهرست کردن فایل‌ها، خواندنشان، جست‌وجو — بدون هیچ
  پیامی.
- **نوشتن می‌پرسد.** قبل از اینکه اتفاق بیفتد diff را می‌بینید.
- **اجرای یک فرمان بلندتر می‌پرسد**، و رسیدن به شبکه یا راندن صفحهٔ شما هم
  همین‌طور.
- **هر چیز برگشت‌پذیر، با `/undo` برگردانده می‌شود.**
- **نمی‌تواند از پوشهٔ پروژه بیرون برود** مگر اینکه خودتان آن را خاموش کنید.
- **یک مخزن نمی‌تواند هیچ‌کدام از موارد بالا را تغییر دهد.**

---

## سطوح ریسک

هر ابزار یکی را اعلان می‌کند. سطح تعیین می‌کند قبل از اجرایش چه رخ می‌دهد.

| سطح | ابزارها | چه رخ می‌دهد |
|---|---|---|
| **safe** | `read_file`، `list_dir`، `grep`، `glob`، `todo_write` | اجرا می‌شود |
| **write** | `write_file`، `edit_file` | می‌پرسد، با یک diff |
| **dangerous** | `run_shell`، `run_python`، `web_fetch`، `web_search`، `browse`، `computer` | می‌پرسد |

در **حالت plan**، هر چیزی بالاتر از `safe` قبل از اجرا رد می‌شود. این در لایهٔ
مجوز اعمال می‌شود، نه با خواهش وتمنای مدل برای تظاهر به رفتار درست.

در **حالت chat** اصلاً هیچ ابزاری نیست.

## پیام

```
  Run  pytest tests/ -x
  ────────────────────────────────────────────
  in ~/projects/api-server

  [a] allow   [A] allow always this session   [d] deny
```

`A` برای کل نشست، به تفکیک نوع کار به خاطر می‌سپارد — اجازهٔ نوشتن‌ها اجازهٔ
فرمان‌ها را نمی‌دهد، و اجازهٔ `pytest` اجازهٔ `rm` را نمی‌دهد.

برای اینکه دیگر نپرسد:

```
/approve writes      files yes, commands still ask
/approve shell       commands yes, files still ask
/approve all         everything
```

یا دائمی، در پیکربندی شما:

```json
{
  "safety": {
    "auto_approve_writes": true,
    "auto_approve_shell": false
  }
}
```

### رد کردن به آن یاد می‌دهد

یک رد کردن، روشن‌ترین سیگنالِ ترجیحی است که رابط تا به حال جمع می‌کند. به موتور
یادگیری می‌رود، پس احتمال اینکه عامل دوباره همان چیز را پیشنهاد دهد کمتر می‌شود.
رد کردن کار هدر رفته‌ای نیست.

---

## نقاط بازگشت و `/undo`

تک‌تک فایل‌هایی که عامل می‌نویسد اول نقطهٔ بازگشت دارند — محتوای قبلی، نگه‌داری
شده در `.comodor/checkpoints/` داخل پروژه.

```
/undo
```

آخرین فایلی که عوض کرد را برمی‌گرداند. این کار می‌کند چه نوشتن را تأیید کرده
باشید چه نکرده باشید، و چه تأیید خودکار روشن باشد چه نباشد. همین دلیل قابل‌قبول
بودنِ `/approve all` است.

اگر مجبورید خاموشش کنید:

```json
{ "safety": { "checkpoints": false } }
```

دلیلی خوب برای این کار وجود ندارد.

## مرز فضای کاری

عامل ممکن است **داخل پوشهٔ پروژه و هیچ جای دیگر** بخواند و بنویسد.

ریشهٔ پروژه از جایی که شروع کرده‌اید بالا می‌رود تا چیزی بگوید «این یک پروژه
است» — یک `.git`، یک `pyproject.toml`، یک `package.json`. به شما نشان داده
می‌شود و پرسیده می‌شود، هر پوشه یک بار:

```
  Work in  /home/you/projects/api-server ?
```

پوشه‌های تأییدشده به خاطر سپرده می‌شوند. `--cwd` مستقیماً یکی را نام می‌برد و
نمی‌پرسد.

```json
{ "safety": { "workspace_only": true } }
```

خاموش کردن این، اجازه می‌دهد عامل به کل فایل‌سیستم شما دست بزند. برای دقیقاً
همین دلیل، برای پیکربندیِ یک مخزن ممنوع است.

## فرمان‌هایی که اجرا نخواهد کرد

بعضی چیزها قبل از هر پیامی رد می‌شوند، چون هیچ پیامی نباید بتواند کسی را در
انتهای یک نشست طولانی متقاعد به آن‌ها کند:

```
rm -rf /     rm -rf ~     mkfs        dd if=      shutdown
reboot       format c:    del /f /s /q c:         :(){
> /dev/sda   chmod -R 777 /
```

فهرست کامل `safety.deny_commands` است. مال خودتان را اضافه کنید:

```json
{
  "safety": {
    "deny_commands": ["terraform destroy", "kubectl delete namespace"]
  }
}
```

`safety.allow_commands` سمت دیگر ماجراست — فرمان‌هایی که هرگز نمی‌پرسند:

```json
{ "safety": { "allow_commands": ["git status", "pytest", "ls"] } }
```

## کلیدهای شما

**کجاها زندگی می‌کنند.** `~/.comodor/config.json` خودتان، نوشته‌شده با مجوزهای
فقط‌مالک، یا محیط (environment) شما. هیچ جای دیگری.

**کجاها هرگز نمی‌روند.** نه پیکربندی یک مخزن. نه رابط کاربری. نه یک لاگ.
نه یک `repr` — آن یکی یک باگ واقعی بود، پیدا و تعمیر: هر traceback ای که به
یک Config اشاره می‌کرد کلید را چاپ می‌کرد، و pytest مدام traceback چاپ می‌کند.

**کلیدی که در محیط شما باشد همان‌جا می‌ماند.** اگر `ANTHROPIC_API_KEY` را export
کنید به جای ذخیره کردنش، `/save` آن را در فایل پیکربندی شما کپی نمی‌کند. Export
کردن به جای ذخیره کردن یک تصمیم است و به آن احترام گذاشته می‌شود.

**پوشاندن.** هر چیزی که شبیه یکی از کلیدهای شما به نظر برسد، در خروجی ابزار،
در transcript، و در خروجی‌ها پوشانده می‌شود. روی متن کار می‌کند. نمی‌تواند
پیکسل بخواند — به [استفاده از صفحهٔ شما](computer.md#what-goes-to-the-model)
نگاه کنید.

## یک مخزن چه مجاز است تنظیم کند

یک `.comodor/config.json` داخل پروژه از هر دایرکتوری‌ای خوانده می‌شود که در آن
شروع کرده باشید — که برای یک عامل کدنویسی یعنی *از مخزنی که شخص دیگری نوشته،
بلافاصله بعد از clone کردنش*.

پس محدود شده به چیزهایی که نمی‌توانند علیه شما برگردند:

| یک پروژه مجاز است تنظیم کند | |
|---|---|
| `provider`، `model` | از کدام مدل استفاده شود |
| `agent` | حالت، حلقه، بودجه‌ها، دما، اندازهٔ خروجی |
| `ui` | پوسته، حاشیه‌ها، بنر |
| `learning`، `skills` | روشن باشند یا نه، و محدودیت‌هایشان |
| `mcp.servers` | کدام سرورها استفاده شوند — **به صورت خاموش رسیده‌اند** |

| یک پروژه مجاز به تنظیم **نیست** | چون |
|---|---|
| `providers.*.base_url` | کلید شما با اولین درخواست به سرور آن‌ها می‌رفت |
| `safety.*` | می‌توانست جلوی پرسیدن عامل را بگیرد، یا فهرست رد کردن‌ها را خالی کند |
| `agent.system_prompt_extra` | دستورهایی که با اقتدار شما تزریق می‌شوند |
| `browser.executable` | نام یک باینری که عامل باید راه بیندازد |
| `computer.*` | از ماشینی که همین تازه رویش clone شده، موس شما را می‌خواهد |
| `mcp.enabled` | اعلام یک سرور پیشنهاد است؛ راه انداختنش یک تصمیم |

این یک **فهرست مجاز** است نه یک فهرست منع، پس تنظیمی که سال بعد اضافه شود تا
وقتی کسی تصمیم دیگری نگیرد نامطمئن تلقی می‌شود — درست همان جهتی که اشتباه بودنش
صحیح است.

رد شدن‌ها بلند و آشکار گفته می‌شوند:

```
config: this project cannot set safety, computer — only your own can
```

بی‌صدا نادیده گرفتن فایل یک نفر، همان چیزی است که به یک فایل پیکربندی شهرتِ
«کار نمی‌کند» می‌دهد.

## سقف‌ها

سه‌تا، و بر تک‌تک وظایف اعمال می‌شوند:

```json
{
  "agent": {
    "max_steps": 24,
    "max_seconds": 900,
    "max_cost_usd": 2.0
  }
}
```

**سقف پولی فقط برای مدلی با نرخ منتشرشده کار می‌کند.** برای مدلی که جدول قیمت‌گذاری
نمی‌شناسدش، کنتور هزینه صفر را می‌خواند و سقف هرگز فعال نمی‌شود. کامودور به جای
آنکه بگذارد فکر کنید سقف دارید، همین را می‌گوید:

```
the $2.00 spend limit cannot be enforced for gpt-4o — no published rate is
known, so the cost meter reads zero. The step and time limits still apply.
```

در شروع نشست و در `comodor doctor` گفته می‌شود. به [هزینه](cost.md) نگاه کنید.

## زیرعامل‌ها

`delegate` یک زیرعامل را در یک git worktree اجرا می‌کند — یک نسخهٔ ایزوله از
مخزن. حافظه‌ای ندارد، نمی‌تواند باز هم delegate کند، و **صفحه به او داده
نمی‌شود**: زیرعاملی که در یک worktree کار می‌کند، هیچ کاری به گرفتن موس شما
دارد.
