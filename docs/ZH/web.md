# 从浏览器使用

同一个代理，在浏览器标签页里。在这台机器上，或在一台你通过 SSH 访问的服务器上。

```bash
comodor web
```

打开链接。token 就在里面。

## 选项

```bash
comodor web --port 9000
comodor web --no-browser            # do not open one for me
comodor web --token mytoken         # a fixed token
comodor web --host 0.0.0.0          # reachable from elsewhere — read below
```

---

## Token

每次运行都会生成新的 token，所以昨天的 URL 今天不再是入口。它随 URL 送达，被换取为 Cookie，之后每个请求都由该 Cookie 授权。

想让它在重启后保持稳定：

```bash
export COMODOR_WEB_TOKEN=something-long-and-random
```

拿到 token 的任何人都在那台机器上拥有一个 shell。把它当作 shell 来对待。

---

## 绑定到回环之外

`--host 0.0.0.0` 会把界面放到机器的每个网络接口上。**这个端口是一个 shell。** Comodor 会明确说明这一点，而不是假设你是有意的：

```
  Listening on every address on this machine.
  Anyone who can reach this port can run commands as you.
```

更好的做法，当代理运行在服务器上时：让它留在回环地址，然后建立隧道。

```bash
ssh -N -L 8765:127.0.0.1:8765 you@server
```

然后在本地打开 `http://127.0.0.1:8765`。端口从不暴露，SSH 负责认证。

## 观看它使用屏幕

如果代理正在驱动桌面，它查看的画面帧会出现在界面中，并带有它执行操作位置的标记：

```
┌────────────────────────────────────────────┐
│                                            │
│   [ the screen the model saw ]      ✛      │
│                                            │
│   clicking Save                            │
└────────────────────────────────────────────┘
```

这正是它的意义所在。屏幕上的覆盖层绘制在被驱动的机器上，当那台机器是服务器或容器时毫无用处——面板就是你在别处观看的方式。

每帧画面通过 `/api/screen` 单独获取一次，而不是随事件流传送：一张截图约一兆字节，浏览器若重读事件日志，就得把它看过的每一帧都重新下载一遍。

[使用你的屏幕](computer.md)。

## 它不会做的事

**在没有提供商的情况下启动。** 它可以在已配置好的提供商之间切换，但界面上没有输入密钥的地方，浏览器标签页也不是放密钥的好地方。它不会提供一个在第一个任务上就会失败的 URL，而是说明缺什么然后停止：

```
Comodor has no provider configured, and the browser interface has no way to
add one.

  In Docker, pass a key in as an environment variable:
    -e ANTHROPIC_API_KEY=...    -e OPENAI_API_KEY=...
  or mount a config file at ~/.comodor/config.json.
  Anywhere with a terminal, `comodor setup` asks a few questions.
```

在终端里它会转而提出配置问题。在容器中它总是打印这条消息——容器无论有没有人连接都有一个终端，否则分离运行的容器会在一个没人能回答的问题上永远等待。

**扩大代理可以触及的范围。** 写入和命令的自动批准在 Admin 中显示，却不能在那里修改。权限提示本来就会在每一次操作时、在将要承担后果的人面前提供这个选择；一个任何拿到链接的人都能打开的页面，不适合作为设定长期策略的地方。请到启动 Comodor 的地方修改——参见[安全性](safety.md)。

## 屏幕上有什么

**对话**，随生成随流式显示，围栏代码保持为代码，每次工具调用都是一行，可以点开查看它实际做了什么。

**聊天列表**，在左侧。每段对话都写入 `~/.comodor/sessions`——与终端使用的是同一个文件夹，所以在提示符开始的对话可以在浏览器中打开，反之亦然。搜索深入其中，而不只是看标题。

**Admin**，第二个标签页，它是"这个东西接下来要对我的机器做什么"这个问题的答案：

| | |
|---|---|
| 模型 | 正在回答的是哪个提供商和模型，以及在你持有密钥的提供商之间切换 |
| 运行方式 | 模式、是否自主持续运行，以及四个上限——上下文、步数、时间、花费 |
| 权限 | 它无需询问即可做什么、它会询问什么，以及本会话已授予了什么 |
| 它学到了什么 | 规则、经验、技能、任务，以及其中多少成功了 |
| 工具 | 它能触达的每个工具，按风险用颜色标注，还有你的技能和任何 MCP 服务器 |
| 这台机器 | 版本、Python，以及设置、对话和大脑存放的位置 |

**状态条**，位于底部：页面是否已连接、工作目录、上下文有多满、本次会话花费了多少、有多少条已学习的规则在生效。

**屏幕面板**，当代理正在驱动一个屏幕时——它最后查看的画面帧，带有它即将点击位置的标记。参见[使用你的屏幕](computer.md)。

## 在手机上

同一个页面。低于 900 像素时，聊天列表变成覆盖在对话之上的抽屉，而不是旁边的独立栏，因为 390 像素的屏幕上再占去 292 像素的侧边栏，就没有留下任何能读代码的宽度了。点它外面、按 `Esc`，或使用关闭按钮把它收起。

用你访问机器上其他东西的方式从手机访问它——SSH 隧道，而不是公开绑定。[绑定到回环之外](#binding-to-more-than-loopback)解释了原因。

## 用任何语言书写

用波斯语、阿拉伯语或希伯来语输入时，消息框会随着你输入而翻转方向；这些语言的回答到达时会按从右到左排版。没有任何配置，也没有语言设置：每条消息单独判断，于是在语言之间来回移动的对话会随之移动。

判断靠计数而不是靠首字母，这正是让两个别扭情形得出正确结果的原因——以软件包名开头的波斯语句子仍然是波斯语，而引用了一个波斯语单词的英语句子仍然是英语。代码、路径和 URL 在从右到左的段落内部按从左到右排版，它们本来就属于那里。

阿拉伯文字使用 Vazirmatn 字体，它随软件包携带而不是从字体托管站获取：它必须在一台无法访问互联网的机器上工作。它只作用于阿拉伯文字字符，别的什么都不影响，因此一行混排波斯语和英文标识符的文本会为各自获得正确的字体。
