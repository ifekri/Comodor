# Модели на вашей собственной машине

Comodor может скачать модель, держать её на вашем диске и запускать там — без
ключа, без аккаунта, и она продолжает работать с выдёрнутым сетевым кабелем.

```bash
comodor local list                       # что вы можете запустить и что уже здесь
comodor local get qwen2.5-coder-7b-q4    # скачать её, с полосой прогресса
comodor local use qwen2.5-coder-7b-q4    # сделать её той, с кем говорит агент
```

Тот же список — в браузере под **Admin → Local LLM**, с той же загрузкой, тем же
прогрессом и теми же кнопками.

## Как это устроено и почему это не медленно

Всё заслуживающее доверия делает то же самое — Ollama, LM Studio, llama.cpp,
vLLM — и Comodor тоже: **инференс исполняется в отдельном процессе, говорящем на
OpenAI-совместимом API, и модель остаётся загруженной в нём между запросами.**

Три причины, и все — об отзывчивости агента:

**GIL.** Генерация — длинный привязанный к CPU цикл. Запустить его в собственном
процессе Comodor — и каждый другой поток — перерисовка интерфейса, завершающийся
инструмент, шина событий — ждёт позади него. В другом процессе это проблема
другого ядра.

**Загрузка дорога и должна случаться один раз.** Прочитать четыре гигабайта с
диска и разложить — секунды, а то и десятки секунд. Загружать на каждый запрос —
платить это каждым ходом; постоянно живущий сервер платит один раз и после
отвечает за миллисекунды.

**Падение остаётся там.** Убийство по нехватке памяти на модели 14B завершает
сервер модели, а не вашу сессию. Агент сообщает об ошибке соединения, и
стенограмма переживает это.

Приятное следствие — почти нет нового кода: локальный сервер на
`http://127.0.0.1:PORT/v1` *есть* OpenAI-совместимая конечная точка, поэтому
существующий провайдер гоняет его без изменений. Порт выбирается при старте
сервера, поэтому провайдер `local` не несёт URL в конфигурации — записанный там
оказался бы неверным в следующий раз.

Сервер стартует по **вашему первому сообщению**, а не при запуске. Загружать
четыре гигабайта при каждом запуске `comodor` — включая те разы, когда вы ни о
чём модель не спрашивали, — значило бы дарить пустой экран без причины.

## Что вам нужно

Файл модели, который Comodor скачивает, и что-то, чтобы её запускать. Comodor
использует то, что найдёт:

```bash
brew install llama.cpp          # macOS
winget install llama.cpp        # Windows
                                # Linux: github.com/ggml-org/llama.cpp
```

Ollama или LM Studio, если что-то из этого уже запущено, тоже подходят.
`comodor local list` прямо говорит, когда ничего не доступно, поэтому вы
узнаёте об этом до часа на загрузку, а не после.

## Загрузка

Модель — это от одного до девяти гигабайт по вашей домашней линии, и всё в
загрузке сформировано этим.

**Она возобновляется.** Байты идут в файл `.part`. Остановите её, закройте
ноутбук, потеряйте соединение — следующий `comodor local get` просит сервер
продолжить с того места, где заканчивается тот файл. Браузер показывает
`Resume (37%)` вместо `Download`.

**Она проверяется.** Каждая запись каталога несёт точное число байт и SHA-256, и
файл не принимается, пока не совпадёт. Это не перестраховка: усечённый GGUF
*не* очевидно сломан — он загружается, а затем модель выдаёт бессмыслицу, и вы
проводите вечер, гадая, почему образцовая модель бесполезна. Файл, не прошедший
проверку, удаляется, а не оставляется, чтобы найти его позже и наполовину
доверять.

**За ней можно наблюдать.** В терминале — полоса с четырьмя числами, отвечающими
на заданный вопрос:

```
qwen2.5-coder-7b-q4 ━━━━━━━━━━━━━━╸────────  38.2%  1.7/4.4 GB  8.9 MB/s  0:05:12
```

В браузере те же числа под полосой на карточке модели, обновляемые из потока
событий, а не опросом.

## Куда идут файлы

Один каталог, общий для всех проектов на машине — иначе та же модель в трёх
checkout'ах была бы тремя копиями тех же байтов.

```bash
comodor local where
```

`comodor local remove <id>` удаляет одну и говорит, сколько вернулось.

## Добавление модели в список

Список — это JSON-файл, поэтому новая модель — правка, а не релиз. Его подхватывают
и терминал, и браузер.

```json
{
  "id": "my-model-q4",
  "name": "My Model 7B",
  "description": "One sentence on what it is good at, and what it is not.",
  "url": "https://huggingface.co/OWNER/REPO/resolve/main/file.gguf",
  "size": 4683074336,
  "sha256": "1664fccab734674a...",
  "context": 32768,
  "parameters": "7B",
  "quantization": "Q4_K_M",
  "needs_ram_gb": 8,
  "license": "apache-2.0",
  "good_at": ["code"],
  "tools": true,
  "vision": false
}
```

`id`, `name`, `url` и `size` обязательны — всё остальное опционально, и всё, что
вы опустили, сообщается как неизвестное, а не угадывается. Ошибка в числе здесь
стоит кому-то загрузки и падения.

Размер и контрольную сумму берите из API, а не набирайте:

```bash
curl -s 'https://huggingface.co/api/models/OWNER/REPO?blobs=true' | python -c \
  "import json,sys;[print(f['rfilename'], f['size'], f.get('lfs',{}).get('sha256')) \
   for f in json.load(sys.stdin)['siblings'] if f['rfilename'].endswith('.gguf')]"
```

Два правила, которые проводит загрузчик:

- **Только `https`.** Файл модели — исполняемый артефакт во всём, что важно, и
  полученный по каналу, который кто-то может переписать на лету, — не то, что
  разрешают потому, что каталог попросил.
- **Одна плохая запись не стоит списка.** Некорректная модель пропускается, а
  остальное загружается, потому что альтернатива — пустой список выбора.

Comodor поставляет копию списка и раз в день ищет более свежую, кэшируя найденное.
Без сети он использует кэш, а при неудаче — поставленную копию, в чём и есть весь
смысл её поставлять.

## Чего он не будет делать

`needs_ram_gb` проверяется по вашей машине до старта загрузки, и модель, которая
не поместится, скажет об этом, вместо того чтобы дать вам провести час за
выяснением. `comodor local get --yes` отменяет это, если вы не согласны.

Диск проверяется так же, с одной десятой про запас: загрузка, заполнившая
последний байт диска, не просто падает — она уносит с собой остальную машину.
