# С телефона

Comodor можно управлять через бота Telegram: отправьте ему задачу, наблюдайте,
как он работает, отвечайте на его вопросы и останавливайте его — не открывая
терминала.

**Настройка первого запуска спрашивает об этом.** Последний из шести вопросов
предлагает подключить бота, проверяет токен в Telegram тут же и привязывает вашу
учётную запись до окончания мастера. Если вы ответили *Not now* или настраиваете
машину, которая уже настроена:

```bash
comodor telegram connect <token>   # бот от @BotFather
comodor telegram pair              # добавить вашу учётную запись
comodor telegram start             # запустить его
```

Он запускает ту же сессию агента, что и браузерный интерфейс. Всё — кнопки;
набирать нужно только саму задачу.

## Получение бота

Напишите [@BotFather](https://t.me/botfather) в Telegram, отправьте `/newbot`,
дайте ему имя и имя пользователя с окончанием `bot`. Он ответит токеном:

```
1234567890:AAF…
```

```bash
comodor telegram connect 1234567890:AAF…
```

## Привязка

**Имя пользователя бота публично.** Любой, кто его найдёт, может отправить ему
сообщение, а этот умеет читать ваши файлы. Поэтому он отвечает на фиксированный
список числовых Telegram user id и никому больше.

```bash
comodor telegram pair
```

Он печатает шестизначный код. Отправьте его своему боту в Telegram, и ваша
учётная запись добавлена. Код срабатывает один раз и истекает через пять минут.

Все остальные получают **тишину** — не отказ. Бот, который говорит «вам не
разрешено», сообщил незнакомцу, что существует, что он — Comodor и что есть
список, попасть в который стоило бы.

```bash
comodor telegram status         # кто может с ним говорить
comodor telegram forget 12345   # отозвать одну учётную запись
comodor telegram forget all     # отозвать всех
```

## Что он может и чего не может

**По умолчанию он читает и планирует, и ничего не меняет.** Сессия Telegram
удерживается в режиме плана, что бы ни было задано терминалу.

Это намеренно. Одобрить команду оболочки большим пальцем, на телефоне, в очереди
— решение, принятое с меньшим вниманием, чем то же одобрение у клавиатуры, — а
последствия идентичны.

```bash
comodor telegram writes on      # позволить ему править файлы и исполнять команды
comodor telegram writes off
```

С включёнными записями он всё равно сначала спрашивает, и одобрение — кнопка в
чате:

```
Comodor wants to run
  npm test

  ✓  Yes, once
  ✓✓ Yes, and stop asking this session
  ✗  No
```

Самое широкое обязательство — никогда не первая кнопка под вашим большим пальцем:
на телефоне они близко, а «всегда» нельзя отменить.

## Кнопки

`/start` отвечает моделью, папкой и тем, что ему разрешено, и настройками под
этим. Они на первом экране, а не за кнопкой *Settings*, потому что то, на что
указан бот, — первое, что все хотят узнать, и первое, что они хотят изменить.

| | |
|---|---|
| **New chat** | Забыть разговор до сих пор |
| **History** | Открыть заново любой прежний разговор, целиком |
| **Stop** | Прервать то, что выполняется — заменяет *New chat*, пока тот идёт |
| **Mode** | Действовать, планировать или болтать, каждое прописано словами |
| **Status** | Модель, папка, контекст, траты |
| **Model** | Каждая модель, которую предлагает провайдер; коснитесь, чтобы переключить |
| **Folder** | Какому проекту он ограничен |
| **Skills** | Установить или удалить один из библиотеки |
| **Rules** | Чему он научился из ваших поправок и сколько |
| **Settings** | Остальное — стоимость и что ему можно |
| **Help** | Что делает всё, не покидая чат |

Когда агенту нужно решение, он спрашивает тоже кнопками — те же вопросы, что
задал бы в терминале, по одному на экран, с **Write my own** на всё, чего он не
предвидел.

Списки длиннее экрана — модели, навыки, история — разбиваются на страницы по
шесть, с **Previous** и **Next**. Telegram охотно отрисует восемьдесят кнопок, и
никто не будет их прокручивать.

## Запуск

Три способа, по возрастанию того, как долго он должен жить.

```bash
comodor telegram start                # здесь, удерживая этот терминал
comodor telegram start --background   # отсоединённо; переживёт закрытие терминала
comodor telegram service install      # стартует при каждом входе, переживёт перезагрузку
```

**На переднем плане** он удерживает терминал и показывает, что делает. Это тот
случай для настройки и тот, к которому возвращаться, когда что-то не работает.

**В фоне** это тот же процесс, отсоединённый от запустившего его терминала,
пишущий в журнал вместо экрана. Закрытие терминала, выход из системы, завершение
сессии — ничто из этого не заберёт его с собой.

```bash
comodor telegram stop        # завершить его
comodor telegram status      # работает ли, с каких пор и под каким pid
```

Журнал — `telegram.log` рядом с вашей конфигурацией, и он дополняется, а не
заменяется — причина, по которой бот остановился вчера вечером, находится в
строках, которые перезапуск иначе стёр бы.

**При входе** — работа операционной системы, не наша: ничто, запущенное
программой для самой себя, не переживёт перезапуск машины.

```bash
comodor telegram service show        # прочитать unit, прежде чем доверять
comodor telegram service install
comodor telegram service uninstall
```

| | |
|---|---|
| Linux | **пользовательский** unit systemd в `~/.config/systemd/user` |
| macOS | LaunchAgent в `~/Library/LaunchAgents` |
| Windows | задача планировщика Task Scheduler, запускаемая при входе |

Пользовательская служба на всех трёх, никогда не системная. Системная служба
работает от root или SYSTEM, а это агент, читающий и пишущий ваши файлы с
вашими учётными данными — больше полномочий, чем у человека, владеющего этими
файлами, не даёт ничего и стоит всего, если однажды ошибётся.

`service show` печатает unit прежде, чем `service install` его запишет. Никого
не следует просить доверять определению демона, которое ему не показали.

Папка важна во всех трёх: агент читает и пишет только внутри каталога, в котором
запущен, и это тот каталог, в котором будет работать бот.

## Как он устроен

Без новой зависимости. Bot API — это `getUpdates` в цикле и `sendMessage` через
HTTP-клиент, который у этого проекта уже есть — `python-telegram-bot` был бы
крупнейшей вещью в wheel ради этого.

Ответ правится по таймеру, а не на каждый токен. Telegram берёт round trip за
каждое правление и ограничивает их частоту, поэтому правление на каждый токен
даёт сообщение, которое дросселируется и приходит всё разом в конце.

Бот хранит смещение обновлений и продвигает его по ходу. Без него перезапуск
повторяет каждое сообщение, которое бот когда-либо получил — что для агента,
исполняющего команды, не просто шумно.

## Чего он не будет делать

- Отвечать тому, кто не привязан, или объяснять почему.
- Брать токен или разрешённую учётную запись из `.comodor/config.json`
  проекта. Репозиторий, который мог бы добавить своего автора в этот список,
  был бы задним входом, и, в отличие от браузера или экрана, на экране не было
  бы ничего, чтобы это увидеть.
- Править что-либо до `telegram writes on`.
- Печатать токен. Он в каждом URL Bot API, поэтому из каждой вызванной ошибки
  он вырезается.
