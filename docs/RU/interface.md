# Интерфейс

Что вы видите, что нажимаете и откуда берётся всё, что на экране.

```bash
comodor          # запустить
comodor --demo   # весь интерфейс, офлайн, без ключа
```

Интерфейс работает на [Bun](https://bun.sh) — `comodor doctor` говорит, есть
ли он. Без него `comodor run "..."` выполняет одну задачу без интерфейса, а
`comodor web` отдаёт его в браузер.

Как он устроен — ядро, которым он управляет, протокол между ними и почему
каждый факт на экране принадлежит ядру, а не экрану — описано в
[tui-v2.md](../tui-v2.md). Эта страница — короткая версия для того, кто им
пользуется.

## Экран

```
┌──────────────────────────────────────────┬───────────────────────┐
│ Comodor   ~/work/my-project  fake-1      │ Agents         1 live │
│                                          │  ● d1 running    12.3s│
│  You                                     │    survey the retries │
│  fix the failing parser test             │ Tasks            2/5  │
│                                          │  ◐ write the tests    │
│  Comodor                                 │  ● read the code      │
│  The test expects parse("") to raise, …  │  ○ run the suite      │
│  ✓ read_file  tests/test_parser.py  0.2s │                       │
│  ● run_shell  pytest tests/…     running…│                       │
│      collected 12 items                  │                       │
│                                          │                       │
├──────────────────────────────────────────┴───────────────────────┤
│ ▌ask for anything                                                │
├──────────────────────────────────────────────────────────────────┤
│  [ACT]   PLAN    ASK    Reads, writes and runs commands…         │
│ ● 1 agent  tab Mode  ctrl+b Work  ctrl+k Commands      42% ctx  │
└──────────────────────────────────────────────────────────────────┘
```

**Заголовок** называет проект, а также провайдера и модель, которые отвечают.
Это то, что сообщает ядро, а не то, что говорит файл конфигурации: когда модель
меняется — отсюда, из другого клиента или самим ядром — заголовок следует за
ней.

**Разговор** несёт в себе ленту инструментов. Каждый вызов инструмента стоит
там, где произошёл, одной строкой: знак (`●` выполняется, `✓` готово, `×`
неудача), имя, однострочная сводка и сколько это заняло. Работающий инструмент
показывает последние строки своего вывода; завершённый сворачивается, а клик по
нему открывает то, что ядро ещё хранит.

**Верстак** — `Ctrl+B` — это работа вне разговора: список задач, который
агент ведёт для себя, и все фоновые агенты, которых он запустил, каждый со
своим состоянием. В узком терминале он открывается поверх разговора, а не
рядом, и та же клавиша его закрывает.

**Подвал** печатает то, что можно нажать, из того же списка, из которого
читаются клавиши, и во что обошлась эта сессия там, где провайдер это измеряет.

## Клавиши

| Клавиша | Делает |
|---|---|
| `Enter` | отправить набранное |
| `Tab` / `Shift+Tab` | следующий / предыдущий режим |
| `Ctrl+K` | палитра команд — каждое действие, с поиском |
| `Ctrl+B` | открыть или закрыть верстак |
| `End` | назад к самому новому выводу после прокрутки вверх |
| `PageUp` / `PageDown` | прокрутка разговора |
| `Ctrl+R` | отправить снова сообщение, которое ядро отклонило |
| `Ctrl+C` | остановить то, что он делает; выйти, когда он бездействует |
| `Ctrl+D` | выйти |
| `Esc` | закрыть палитру, выйти из поля или взять безопасный вариант карточки |

Каждое сочетание, которое показывает подвал, существует; подсказку для
непривязанной клавиши напечатать нельзя.

## Режимы

```
ACT    читает, пишет и выполняет команды, спрашивая перед тем, как что-то менять
PLAN   читает и планирует; не может писать, выполнять или что-то менять
ASK    обсуждает; никаких инструментов
```

`Tab` переключает их по кругу. Метка сдвигается, когда ядро подтверждает, а не
когда нажата клавиша: нажатия внутри одного обмена накапливаются — три Tab
спрашивают один раз, о том, куда указывал третий, — а отклонённое изменение
говорит об этом словами, а не сдвигом метки.

---

## Когда он о чём-то спрашивает

Карточка разрешения или форма с вопросами забирает клавиатуру, пока открыта,
чтобы клавиша, предназначенная для решения, не могла заодно отправить
сообщение.

- **Стрелки** переходят между вариантами или вопросами; **Enter**
  отправляет.
- **Esc** берёт безопасный вариант самого запроса — для разрешения это
  *отказать*, для предложенной смены режима — *без изменений*, — и карточка
  говорит, какой именно. Он никогда ничего не разрешает.
- Одноклавишного сочетания для *разрешить* нет. Разрешение стоит одного
  перехода к варианту и одного для подтверждения, чтобы клавиша, нажатая по
  любой другой причине, не могла санкционировать команду.
- Вопрос, предлагающий строку «напишите своё», открывает для неё поле по
  `Space`; `Esc` выходит из поля прежде, чем отменит форму.

Ждать могут двое сразу — два параллельных инструмента могут спросить каждый —
и они показываются в порядке поступления, ни один не теряется.

Клавиши режимов продолжают работать, пока открыта карточка. Палитра — нет:
лаунчер поверх решения скрыл бы то, на что нужно ответить.

## Следить за выводом

Длинный ответ держит самую новую строку на виду. Прокрутите вверх — и он
перестаёт следовать; новый вывод не утаскивает вас вниз, а маркер говорит, что
ниже есть ещё. `End` возвращает к живому хвосту, и отправка нового сообщения
делает то же.

---

## Сессии

`Ctrl+K` → *Открыть прошлый разговор* перечисляет то, что ядро сохранило, и
открывает один на месте. То же хранилище обслуживает браузер, так что разговор,
начатый здесь, можно снова открыть там.

`comodor --resume` при запуске открывает самый свежий; `--resume ID` называет
конкретный.

---

## Копирование текста

Выделяйте мышью так, как позволяет ваш терминал. Флаги `--theme` и `--ascii`
относятся к тому, что печатают команды — `setup`, `doctor`, `help`, — а не к
интерфейсу, который рисует из собственных дизайн-токенов.

---

## Текст справа налево

Персидский, арабский и смешанные строки передаются терминалу как написаны и
никогда не переворачиваются программой. Насколько хорошо формируется смешанная
строка — дело терминала, и те, что делают это хорошо, делают это хорошо и здесь.
