# В вашем редакторе

Comodor говорит на [Agent Client Protocol](https://agentclientprotocol.com), поэтому
редактор с его поддержкой может управлять Comodor напрямую — со своей панелью,
своими запросами разрешений, своим просмотром файлов — с тем же агентом, теми же
выученными правилами и теми же стенограммами, что и в терминале.

```bash
comodor acp
```

Обычно вам не придётся вводить это. Редактор запускает его сам.

---

## Настройка

Comodor выводит блок, который запрашивает ваш редактор:

```bash
comodor acp --print-config
```

```json
{
  "agent_servers": {
    "Comodor": {
      "command": "/home/you/.local/bin/comodor",
      "args": ["acp"],
      "env": {}
    }
  }
}
```

Куда его положить, зависит от редактора. Три, которые были настроены и проверены
на реальной машине во время написания этого текста:

**JetBrains** — PyCharm, IntelliJ, WebStorm и остальные, через плагин AI
Assistant. Поместите блок в `~/.jetbrains/acp.json` или выберите *Add Custom
Agent* в меню окна AI Chat — откроется тот же файл. После этого Comodor появится
в списке агентов внизу панели чата. Подписка JetBrains AI для этого не нужна —
агенты ACP работают и без неё.

**VS Code** — установите расширение-клиент ACP; [ACP
Client](https://marketplace.visualstudio.com/items?itemName=formulahendry.acp-client)
— то, на чём это проверялось. Блок добавляется в `acp.agents` в
`settings.json`, и Comodor появляется в списке агентов панели ACP.

**Zed** — `settings.json`, и Comodor появляется в панели агентов.

Также сообщается о работоспособности, хотя здесь это не проверялось: Neovim
(CodeCompanion, avante.nvim, agentic.nvim), Emacs (agent-shell.el), Qt Creator,
Obsidian и Visual Studio.

Протокол везде один и тот же; отличается только файл настроек.

Сначала настройте Comodor в терминале:

```bash
comodor setup
```

Редактору некуда спросить, какой провайдер использовать, поэтому Comodor, который
ещё ни разу не был настроен, откажется начинать сессию и скажет, какую команду
запустить. Это понятное сообщение в редакторе, а не провал на первой же задаче.

---

## Что получает редактор

| | |
|---|---|
| Потоковые ответы | по мере того, как их пишет модель |
| Вызовы инструментов | каждый назван, с указанием, что он сделал, и пометкой read / edit / execute, чтобы редактор мог подобрать значок |
| Запросы разрешений | спрашивается в редакторе, отвечается в редакторе |
| Планы | когда Comodor составляет список задач, редактор его отрисовывает |
| Отмена | кнопка остановки редактора прерывает ход |
| Сессии | перечисляются, возобновляются и удаляются — те же стенограммы, что возобновляет `comodor` |

Рабочая папка приходит из редактора: тот проект, который у вас открыт, — там
агент читает и пишет, и он ограничен им.

---

## Чего он не делает

**Не берёт провайдера модели у редактора.** Провайдер, модель, правила, навыки и
разрешения Comodor — его собственные, настраиваемые через `comodor setup` или в
браузерном интерфейсе. Редактор, который тоже захочет настроить модель, стал бы
вторым источником истины для той же настройки.

**Не выполняет вход.** Comodor аутентифицируется у провайдера модели, а не в
вашем редакторе, поэтому он не объявляет методов аутентификации, и клиент не
предложит вам выполнить вход.

---

## Когда что-то не так

Протокол резервирует стандартный вывод для сообщений, поэтому журналы Comodor
идут в стандартный поток ошибок. Редакторы обычно показывают его где-то — в Zed
это журнал сервера агента.

```
comodor acp — speaking ACP v2 on stdio
```

Распространённый случай, который выглядит как сломанный агент, а не тем, чем
является: провайдер отклоняет ваш ключ. Он приходит в редактор как `Error during
prompt turn` или словами самого провайдера — например, `OpenRouter: User not
found`, что означает, что ключ был отозван. `comodor doctor` скажет, какой
провайдер настроен; браузерный интерфейс примет новый ключ или выполнит вход.

Если агент подключился и затем ничего не делает, сначала запустите `comodor
doctor` в терминале: недоступный провайдер из редактора выглядит так же, как
сломанный агент.
