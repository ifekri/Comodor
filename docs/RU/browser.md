# Настоящий браузер

Не загрузчик страниц. Браузер, который реально установлен — он исполняет
JavaScript, хранит cookie-файлы и умеет выполнять вход.

---

## Что он использует

Chrome, Chromium, Edge или Brave — что есть на машине. **Ничего не
загружается.** Он запускает один из них в собственном профиле, не входящем никуда,
и закрывает его по окончании сессии.

Если ничего не установлено, `browse` переключается на текстовый браузер, который
всё равно отвечает на большинство вопросов о странице. Оба называются `browse`,
потому что выбирать между двумя сущностями с именем «browser» — это ход, который
модели не стоит тратить.

---

## Что возвращается

Не скриншот. Заголовок, читаемый текст и **пронумерованный список элементов
управления, реально находящихся на экране**:

```
  Sign in — Example
  ─────────────────────────────────────────────
  Sign in to your account. New here? Create one.

  [1]  textbox   Email
  [2]  textbox   Password
  [3]  button    Sign in
  [4]  link      Forgot your password?
```

Модель действует с одним из них по номеру. Этот список отфильтрован до видимого,
названного, находящегося на экране и не дублирующегося — что куда меньше
дерева доступности и, по измерениям, меньше скриншота той же страницы.

Скриншот — только когда вопрос визуальный: вёрстка, стили, график — потому что
картинка стоит одинаково каждый раз и не может быть сокращена.

## Глаголы

| | |
|---|---|
| `open` | перейти по URL |
| `click` | элемент управления, по его номеру |
| `type` | в поле, по его номеру |
| `scroll` | вверх или вниз |
| `back` | предыдущая страница |
| `read` | страницу снова, после того как что-то изменилось |
| `look` | скриншот, когда вопрос о том, как это выглядит |
| `script` | исполнить JavaScript и получить его значение |

## Наблюдая за работой

```json
{ "browser": { "headless": false } }
```

Видимое окно, чтобы вы могли видеть, что он делает.

> Эта настройка раньше игнорировалась — `browser` не был зарегистрирован как
> секция конфигурации, поэтому любая настройка `browser` молча ничего не делала.
> Исправлено в 0.9.0.

## Использование сессии, в которой вы уже вошли

Вместо того чтобы отдавать свой профиль, запустите свой браузер с портом DevTools
и укажите Comodor на него:

```bash
chrome --remote-debugging-port=9222
```

```json
{ "browser": { "port": 9222 } }
```

Он подключается к этому браузеру и использует уже имеющиеся вкладки и cookie-файлы.
Закройте порт, когда закончите — любой процесс на вашей машине может его
использовать.

## Все настройки

```json
{
  "browser": {
    "executable": "",
    "headless": true,
    "width": 1280,
    "height": 800,
    "port": 0
  }
}
```

| | |
|---|---|
| `executable` | конкретный браузер. Пусто означает искать в обычных местах |
| `headless` | по умолчанию невидим, чтобы не перехватывать фокус |
| `width`, `height` | окно |
| `port` | подключаться к запущенному вами браузеру вместо запуска своего |

Репозиторий не может задать ни одну из них — `browser.executable` называет
бинарный файл для запуска. [Безопасность](safety.md#what-a-repository-may-set).

## `browse` или `web_fetch`?

| | |
|---|---|
| `web_fetch` | страница — документ. Сводит её к тексту. Дёшево |
| `browse` | страница — приложение. Нужны JavaScript, вход или клик |

Модели сказано предпочитать `web_fetch` и браться за `browse`, когда тот не
подойдёт.

## В контейнере

В образ Docker входят Chromium и шрифты для рендеринга. Собственная песочница
Chromium не может стартовать внутри контейнера, чей профиль seccomp блокирует
пользовательские пространства имён, поэтому Comodor обнаруживает это и повторяет
запуск без внутренней песочницы — сохраняя изоляцию контейнера, которая и есть
настоящая граница. [Docker](docker.md).

---

## Под капотом

Chrome DevTools Protocol поверх написанного вручную WebSocket. Без зависимостей:
обрамление RFC 6455 — это примерно сто строк, и оно входит в пакет, так же как
HTTP-клиент и чтение SSE.
