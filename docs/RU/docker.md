# В Docker

Агент, его браузер и всё, что ему нужно, в одном контейнере.

```bash
git clone https://github.com/ifekri/Comodor.git
cd Comodor
export ANTHROPIC_API_KEY=…        # or OPENAI_API_KEY, OPENROUTER_API_KEY, …
docker compose up
```

При первом запуске он собирает образ, затем печатает адрес:

```
  Comodor is at  http://127.0.0.1:8765/?token=…
  Working in     /work
```

Откройте ссылку. При каждом запуске новый токен, поэтому используйте токен
именно *этого* запуска.

Или без клонирования чего-либо:

```bash
docker run --rm -it -p 127.0.0.1:8765:8765 \
  -e ANTHROPIC_API_KEY \
  -v "$PWD:/work" \
  ghcr.io/ifekri/comodor:latest
```

---

## Ключ — или страница сама его попросит

Задайте его, и всё готово, как только вы откроете ссылку. Без него
контейнер всё равно запустится, а ключ попросит страница — браузерный
интерфейс теперь умеет его принимать, и контейнер, который отказывался
стартовать, был недоступен именно тому, кому он нужнее всего: тому, у
кого Comodor стоит на сервере, без терминала перед глазами.

Логи говорят об этом ещё до того, как вы что-либо откроете:

```
No provider is configured yet — the page will ask when you open it.
```

Compose пробрасывает тот из них, который задан в вашей оболочке, не записывая
его в образ или в файл compose:

```
ANTHROPIC_API_KEY   OPENAI_API_KEY   OPENROUTER_API_KEY   DEEPSEEK_API_KEY
GOOGLE_API_KEY      GROQ_API_KEY     XAI_API_KEY          MISTRAL_API_KEY
XIAOMI_API_KEY
```

Предпочитаете файл истории оболочки? Положите его в `.env` рядом с файлом
compose — compose читает его, и он игнорируется git.

---

## Где он работает

Всё, чего может коснуться агент, — это папка `work/` рядом с файлом compose.
Укажите на другое место:

```yaml
volumes:
  - "/path/to/your/project:/work"
```

Чему он учится — мозг, ваши поправки, стенограммы сессий — живёт в именованном
томе, поэтому это переживёт `docker compose down` и будет забыто командой
`docker compose down -v`.

## Кто может до него добраться

```yaml
ports:
  - "127.0.0.1:8765:8765"
```

**`127.0.0.1` слева — и есть вся модель безопасности.** Уберите его, и порт
окажется на каждом интерфейсе машины — а этот порт есть оболочка.

Внутри контейнера Comodor привязывается к `0.0.0.0`, и это не упущение: у
контейнера своё сетевое пространство имён, поэтому привязка к loopback внутри
него прячет порт от машины, которая его запускает. Кому фактически можно
добраться до него, решается тем, как порт был опубликован, и баннер говорит об
этом.

---

## Что контейнеру можно делать

```yaml
cap_drop: [ALL]
security_opt:
  - no-new-privileges:true
```

Он исполняет команды оболочки, поэтому контейнер — то, что стоит между ними и
вашей машиной. Ему не даётся ничего, что ему не нужно, и он работает от
пользователя без прав root.

## Фиксация версии

```yaml
args:
  COMODOR_VERSION: ""
```

По умолчанию зафиксирована, чтобы пересборка была воспроизводимой. Вместо этого
хотите новейший релиз:

```bash
docker compose build --build-arg COMODOR_VERSION=
```

---

## Запуск чего-то ещё внутри него

```bash
docker compose run --rm comodor comodor doctor
docker compose run --rm comodor sh
```

Без аргументов или аргументы, начинающиеся с дефиса, означают «запустить
веб-интерфейс с этими опциями». Всё остальное — команда для запуска вместо него.

---

## Чего в контейнере нет

**Вашего экрана.** [Управление рабочим столом](computer.md) управляет машиной,
на которой Comodor запущен, а в контейнере это машина без дисплея. Там
инструмент не предлагается.

[Браузер](browser.md) работает — Chromium и его шрифты есть в образе.

---

## Если он не запускается

**Ничего на `localhost:8765`** — проверьте, что порт опубликован:
`docker compose ps`.

**Завершается сразу** — читайте журнал. Почти всегда не настроен провайдер;
сообщение говорит, что задать.

**`exec /usr/local/bin/comodor-start: no such file or directory`** — checkout с
CRLF. Исправлено в ветке с `.gitattributes`; если видите это, потяните обновления.
