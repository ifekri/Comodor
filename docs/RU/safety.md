# Безопасность и разрешения

Что Comodor может сделать с вашей машиной, о чём он спрашивает сначала и чего он
не сделает, что бы вы ни сказали.

---

## Короткая версия

- **Чтение проходит молча.** Список файлов, их чтение, поиск — без запроса.
- **Запись спрашивает.** Вы видите diff до того, как он произойдёт.
- **Выполнение команды спрашивает громче**, как и выход в сеть или управление
  вашим экраном.
- **Всё обратимое отменяется через `/undo`.**
- **Он не может покинуть папку проекта**, если вы это не отключите.
- **Репозиторий не может изменить ничего из перечисленного.**

---

## Уровни риска

Каждый инструмент объявляет свой. Уровень решает, что происходит перед его
запуском.

| Уровень | Инструменты | Что происходит |
|---|---|---|
| **safe** | `read_file`, `list_dir`, `grep`, `glob`, `todo_write` | выполняется |
| **write** | `write_file`, `edit_file` | спрашивает, с diff |
| **dangerous** | `run_shell`, `run_python`, `web_fetch`, `web_search`, `browse`, `computer` | спрашивает |

В **режиме plan** всё выше `safe` отклоняется до запуска. Это обеспечивается на
уровне разрешений, а не просьбой к модели вести себя хорошо.

В **режиме chat** инструментов нет вовсе.

## Запрос подтверждения

```
  Run  pytest tests/ -x
  ────────────────────────────────────────────
  in ~/projects/api-server

  [a] allow   [A] allow always this session   [d] deny
```

`A` запоминается на сессию по каждому типу действий — разрешение записей не
разрешает команды, а разрешение `pytest` не разрешает `rm`.

Чтобы перестать получать вопросы:

```
/approve writes      файлы — да, команды всё ещё спрашивают
/approve shell       команды — да, файлы всё ещё спрашивают
/approve all         всё
```

Или навсегда, в вашей конфигурации:

```json
{
  "safety": {
    "auto_approve_writes": true,
    "auto_approve_shell": false
  }
}
```

### Отказ обучает его

Отказ — самый ясный сигнал предпочтения, который интерфейс вообще собирает. Он
попадает в механизм обучения, так что агент с меньшей вероятностью предложит то
же самое снова. Отказ — не потраченное впустую усилие.

## Контрольные точки и `/undo`

Каждый файл, который пишет агент, сначала фиксируется контрольной точкой —
прежнее содержимое, хранимое под `.comodor/checkpoints/` в проекте.

```
/undo
```

восстанавливает последний изменённый им файл. Это работает и когда вы
подтвердили запись, и когда нет, и при включённом авто-подтверждении тоже. Это
причина, по которой `/approve all` — разумная вещь.

Выключить, если уж очень надо:

```json
{ "safety": { "checkpoints": false } }
```

Хорошей причины нет.

## Граница рабочего пространства

Агент может читать и писать **внутри папки проекта и нигде больше**.

Корень проекта находится подъёмом от места, где вы начали, пока что-то не скажет
«это проект» — `.git`, `pyproject.toml`, `package.json`. Его вам показывают и
спрашивают, один раз для каждой папки:

```
  Work in  /home/you/projects/api-server ?
```

Одобренные папки запоминаются. `--cwd` называет папку напрямую и не спрашивает.

```json
{ "safety": { "workspace_only": true } }
```

Выключение этого позволяет агенту трогать всю вашу файловую систему. Именно
поэтому для конфигурации репозитория это вне закона.

---

## Команды, которые он не выполнит

Некоторые вещи отклоняются до появления любого запроса, потому что никакой
запрос не должен уметь уговорить человека на них в конце долгой сессии:

```
rm -rf /     rm -rf ~     mkfs        dd if=      shutdown
reboot       format c:    del /f /s /q c:         :(){
> /dev/sda   chmod -R 777 /
```

Полный список — `safety.deny_commands`. Добавьте свои:

```json
{
  "safety": {
    "deny_commands": ["terraform destroy", "kubectl delete namespace"]
  }
}
```

`safety.allow_commands` — в другую сторону — команды, которые никогда не
спрашивают:

```json
{ "safety": { "allow_commands": ["git status", "pytest", "ls"] } }
```

## Ваши ключи

**Где они живут.** Ваш собственный `~/.comodor/config.json`, записанный с правами
только для владельца, или ваше окружение. Нигде больше.

**Куда они никогда не попадают.** Не в конфигурацию репозитория. Не в интерфейс.
Не в лог. Не в `repr` — это был настоящий баг, найденный и исправленный: любой
трейсбек, называвший Config, раньше печатал ключ, а pytest печатает трейсбеки
постоянно.

**Ключ в вашем окружении остаётся там.** Если вы экспортируете
`ANTHROPIC_API_KEY`, а не сохраняете его, `/save` не скопирует его в ваш файл
конфигурации. Экспортировать, а не сохранять, — это решение, и оно уважается.

**Сокрытие.** Всё, что похоже на один из ваших ключей, маскируется в выводе
инструментов, в транскрипте и в экспортах. Это работает на тексте. Оно не умеет
читать пиксели — см. [Использование экрана](computer.md#what-goes-to-the-model).

## Что репозиторий может задавать

`.comodor/config.json` в проекте читается из того каталога, где вы начали, — а
для агента по программированию это значит *из репозитория, написанного кем-то
другим, сразу после клонирования*.

Поэтому он ограничен тем, что нельзя обратить против вас:

| Проект может задавать | |
|---|---|
| `provider`, `model` | какую модель использовать |
| `agent` | режим, loop, бюджеты, температуру, размер вывода |
| `ui` | тему, рамки, баннер |
| `learning`, `skills` | включены ли они, и их лимиты |
| `mcp.servers` | какие серверы он использует — **прибывающими выключенными** |

| Проект **не может** задавать | потому что |
|---|---|
| `providers.*.base_url` | ваш ключ ушёл бы на их сервер при первом же запросе |
| `safety.*` | он мог бы остановить вопросы агента или опустошить список запретов |
| `agent.system_prompt_extra` | инструкции, внедрённые с вашими полномочиями |
| `browser.executable` | он называет бинарник, который агент запустит |
| `computer.*` | он просит у машины, на которую его только что склонировали, вашу мышь |
| `mcp.enabled` | объявить сервер — предложение; запустить его — решение |

Это **белый список**, а не чёрный, так что настройка, добавленная в следующем
году, недоверена, пока кто-то не решит иначе, — правильная сторона, на которой
лучше ошибаться.

Отказы произносятся вслух:

```
config: this project cannot set safety, computer — only your own can
```

Молча игнорировать чужой файл — вот как файл конфигурации зарабатывает репутацию
не работающего.

## Потолки

Три, и они действуют на каждую задачу:

```json
{
  "agent": {
    "max_steps": 24,
    "max_seconds": 900,
    "max_cost_usd": 2.0
  }
}
```

**Денежный работает только для модели с опубликованным тарифом.** Для модели,
которой таблица цен не знает, счётчик расходов читает ноль, и лимит не срабатывает
никогда. Comodor так и говорит, вместо того чтобы позволить вам верить, что у вас
есть потолок:

```
the $2.00 spend limit cannot be enforced for gpt-4o — no published rate is
known, so the cost meter reads zero. The step and time limits still apply.
```

Это говорится в начале сессии и в `comodor doctor`. См. [Стоимость](cost.md).

## Суб-агенты

`delegate` запускает суб-агента в git worktree — изолированной копии репозитория.
У него нет памяти, он не может делегировать дальше, и **ему не даётся экран**:
суб-агенту, работающему в worktree, незачем забирать вашу мышь.
