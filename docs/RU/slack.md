# Из Slack

Тот же агент, в вашем рабочем пространстве: отправьте ему задачу, наблюдайте,
как он работает, отвечайте на его вопросы — не открывая терминала.

```bash
comodor slack manifest              # определение приложения для вставки в Slack
comodor slack connect               # два токена, проверяемые по мере вставки
comodor slack pair                  # добавить вашу учётную запись
comodor slack start --background    # запустить его
```

Около пяти минут, и **публичный адрес устраивать не нужно** — это и отличает
его от [WhatsApp](whatsapp.md).

Он запускает ту же сессию агента, что терминал, браузер и бот Telegram. Задача,
начатая здесь, учится тем же урокам и попадает в ту же историю.

## Почему это просто

У Slack два способа доставки событий. Events API отправляет POST на URL, что
означает публичный HTTPS-адрес, сертификат и туннель — всю работу, делающую
WhatsApp сложным.

**Socket Mode** переворачивает это: приложение запрашивает у Slack адрес
websocket и подключается *наружу*. Ничему не нужно быть доступным из интернета,
и нет адреса, который надо поддерживать актуальным. Весь фокус в этом, и поэтому
Slack стоит рядом с Telegram, а не рядом с WhatsApp.

Второе, что помогает, — **манифест приложения**. Slack позволяет описать
приложение документом YAML, поэтому вместо того, чтобы искать одиннадцать
галочек на четырёх страницах настроек, всё приложение — имя, области, события,
Socket Mode уже включённый — это одна вставка.

## Настройка

### 1. Создайте приложение

```bash
comodor slack manifest
```

Он печатает манифест и ссылку. На
[api.slack.com/apps](https://api.slack.com/apps?new_app=1) выберите **From a
manifest**, укажите своё рабочее пространство, вставьте, создайте — затем
**Install to Workspace**.

### 2. Два токена

Они не взаимозаменяемы, и перепутать их — самый распространённый способ, каким
это ломается. Comodor отвергает каждый, если он вставлен на месте другого, по
имени, вместо того чтобы Slack через час ответил `invalid_auth`.

| | | |
|---|---|---|
| `xoxb-…` | **Bot token** | OAuth & Permissions. Делает всё, что делает бот |
| `xapp-…` | **App-level token** | Basic Information → App-Level Tokens, область `connections:write`. Открывает сокет, и больше ничего |

```bash
comodor slack connect
```

Без аргументов он проводит вас через оба и проверяет каждый по прибытии —
токен бота через `auth.test`, токен приложения фактическим открытием сокета с
ним. Неверный — это фраза сейчас, а не загадка на следующей неделе.

### 3. Привяжите свою учётную запись

```bash
comodor slack pair
```

Он печатает шестизначный код. Отправьте его Comodor личным сообщением, и ваша
учётная запись добавлена. Код срабатывает один раз и истекает через пять минут.

**В рабочем пространстве могут быть сотни людей**, а это агент, читающий и
пишущий ваши файлы. Поэтому он отвечает на фиксированный список Slack user id
и игнорирует всех остальных.

```bash
comodor slack status
comodor slack forget U01234567
comodor slack forget all
```

## Где он отвечает

**В личном сообщении**, всегда.

**В канале — только когда упомянут.** Бот, отвечающий на каждое сообщение в
общем канале, — бот, который кто-нибудь удалит в тот же день.

**В треде, в котором к нему обратились.** Вопрос, заданный в треде, получает
ответ в том же треде, а не в канале перед всеми.

Свои собственные сообщения он не отвечает никогда — бот, отвечающий самому
себе, — цикл с ограничением частоты.

## Что он может и чего не может

**По умолчанию он читает и планирует, и ничего не меняет.** Сессия Slack
удерживается в режиме плана, что бы ни было задано терминалу, по той же причине,
что и в других каналах: одобрить команду оболочки с телефона, в очереди, —
решение, принятое с меньшим вниманием, чем то же одобрение у клавиатуры.

```bash
comodor slack writes on
comodor slack writes off
```

Терминальная команда намеренно. Бот, который мог бы расширять собственные
разрешения, нуждался бы лишь в чьём-то аккаунте Slack.

## Кнопки

Slack — самый просторный из трёх каналов: сообщения можно править, а кнопок
много, поэтому ответ — одно сообщение, растущее по мере поступления ответа, и
всё меню помещается на один экран.

| | |
|---|---|
| **New chat** | Забыть разговор до сих пор |
| **History** | Открыть заново прежний разговор |
| **Mode** | Действовать, планировать или болтать |
| **Status** | Модель, папка, контекст, траты |
| **Model** | Переключиться на другую |
| **Folder** | В каком проекте он работает |
| **Skills** | Установить или удалить один |
| **Rules** | Чему он научился из ваших поправок |
| **What it may do** | Может ли он править и исполнять |
| **Help** | Что делает всё |

Пока задача выполняется, предлагается только **Stop**.

## Запуск

```bash
comodor slack start                # здесь, удерживая этот терминал
comodor slack start --background   # отсоединённо; переживёт закрытие
comodor slack stop
comodor slack service install      # стартует при входе, переживёт перезагрузку
comodor slack service show         # прочитать unit, прежде чем доверять
```

Журнал — `slack.log` рядом с вашей конфигурацией, дополняется, а не заменяется.

**Пользовательская** служба на каждой платформе — systemd, launchd, Task
Scheduler — никогда не системная. Это агент, читающий и пишущий ваши файлы с
вашими учётными данными, и больше полномочий, чем у человека, владеющего этими
файлами, не даёт ничего.

## Из панели браузера

`comodor web` → **Admin** → **From your phone** подключает, привязывает,
запускает и останавливает всё это без терминала. Эти элементы управления
отвечают только на запросы с машины, на которой Comodor запущен: токен бота
отдаёт удалённое управление им тому, кто держит токен.

## Как он устроен

Без новой зависимости. Web API — это `POST /api/chat.postMessage` через
HTTP-клиент, который у этого проекта уже есть, а Socket Mode работает поверх
websocket-клиента, написанного для управления Chrome, — поэтому добавление
Slack не добавило ни пакета.

Три вещи, о которых цикл сокета заботится, каждая — способ, которым бот
замолкает так, что никто не заметит:

- **Каждый конверт подтверждается.** Slack повторно доставляет то, о чём не
  слышал, а для агента, исполняющего команды, одно сообщение, ставшее тремя
  ходами, — не просто шум.
- **`disconnect` — рутина.** Slack меняет соединения по расписанию. Считать это
  отказом — получить бота, умирающего каждые несколько часов.
- **Тихое рабочее пространство всё равно получает пинги.** Самый важный случай —
  никто не писал ему час — ровно тот, который разрушает упавший сокет.

## Чего он не будет делать

- Отвечать тому, кто не привязан.
- Отвечать на всё в канале, в который его добавили.
- Брать токен или разрешённую учётную запись из `.comodor/config.json`
  проекта. Репозиторий, который мог бы добавить своего автора в этот список,
  был бы задним входом.
- Править что-либо до `slack writes on`.
- Печатать любой из токенов. Оба вырезаются из каждой вызванной ошибки.
