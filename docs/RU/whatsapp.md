# Из WhatsApp

Тот же агент, доступный с бизнес-номера WhatsApp: отправьте ему задачу,
наблюдайте, как он работает, отвечайте на его вопросы — не открывая терминала.

> **Сначала прочитайте это.** [Telegram](telegram.md) делает то же самое и
> занимает около минуты: написать @BotFather, вставить один токен. WhatsApp
> занимает около двадцати, требует технических знаний, и большая часть этого — в
> панели Meta: вам нужны приложение Meta, секрет приложения и публичный
> HTTPS-адрес. **Если это не обязательно должен быть WhatsApp — используйте
> Telegram.**
>
> [Slack](slack.md) — средняя дорога: около пяти минут, и публичного адреса
> тоже не нужно.
>
> Обойти это нельзя. У WhatsApp нет эквивалента токена бота, и Meta доставляет
> сообщения на URL, а не позволяет чему-либо опрашивать их. Единственная
> по-настоящему «в один клик» версия пропускала бы каждое сообщение через
> чужой сервер, и это не компромисс, на который идёт этот инструмент.

```bash
comodor whatsapp connect              # проводит вас через всё
comodor whatsapp pair                 # добавить ваш номер
comodor whatsapp start --background   # запустить его
```

`connect` без аргументов — управляемая настройка: она ссылается на каждую
страницу, принимает по одному значению за раз и проверяет каждое по прибытии —
токен в Meta, id на то, что это id, секрет на то, что это секрет. Она запускает
туннель за вас и ждёт, пока callback верификации Meta действительно не придёт,
вместо того чтобы предполагать это.

Он запускает ту же сессию агента, что терминал, браузер и бот Telegram.
Задача, начатая здесь, учится тем же урокам и появляется в той же истории.

## Почему это требует больше настройки, чем Telegram

Telegram даёт вам токен и позволяет опрашивать сообщения. WhatsApp — это
**Cloud API** от Meta, и два его проектных решения формируют здесь всё.

**Сообщения доставляются, а не запрашиваются.** Долгого опроса нет. Meta
отправляет каждое входящее сообщение POST-запросом на URL, что означает, что
что-то ваше должно быть доступно из интернета по HTTPS. Это и есть лишняя
работа, и обойти её нельзя.

**Meta хочет приложение.** Бизнес-аккаунт, номер, токен доступа и секрет
приложения — четыре вещи, живущие в браузере, поэтому мастер первого запуска
указывает на эту страницу, а не пытается их собрать.

Путь, к которому прибегает большинство проектов, — библиотека, управляющая
WhatsApp Web через headless-браузер. Они требуют Node, ломаются всякий раз,
когда WhatsApp меняет свой веб-клиент, и нарушают условия, на которых держится
аккаунт: сценарий отказа — бан номера. Не то, что инструмент для программирования
позволил бы себе вручать своим пользователям.

## Сколько это занимает

Около двадцати минут в первый раз, против одной минуты у Telegram, и большая
часть этого — в панели Meta, а не здесь.

Чего вам **не** нужно: настоящий телефонный номер, способ оплаты или
верификация бизнеса. Добавление продукта WhatsApp создаёт **тестовый номер**,
который бесплатно пишет до пяти получателям, — на четыре больше, чем требует
один человек, разговаривающий со своим собственным агентом.

## Настройка

Кратко: `comodor whatsapp connect`, который проводит через всё. Ниже — то, через
что он проводит, для тех, кто предпочёл бы увидеть сначала.

### 1. Приложение Meta с WhatsApp

На [developers.facebook.com](https://developers.facebook.com) создайте приложение
и добавьте продукт **WhatsApp**. Meta даёт тестовый номер для начала; настоящий
добавляется позже в бизнес-аккаунте.

Вам нужны четыре вещи оттуда:

| | |
|---|---|
| **Phone number id** | Числовой id рядом с номером — *не* сам номер |
| **Access token** | Токен панели живёт 24 часа. Токен **System User** в Business Settings не истекает — используйте его |
| **App secret** | Settings → Basic. Каждый webhook подписан им |
| **Публичный HTTPS-адрес** | Куда Meta доставляет. См. ниже |

```bash
comodor whatsapp connect \
    --number-id 123456789012345 \
    --token EAAG… \
    --app-secret 0a1b2c…
```

Это проверяет токен в Meta прежде, чем что-либо сохранить, так что опечатка —
сообщение сейчас, а не загадка на следующей неделе.

### 2. Куда-то, куда Meta будет доставлять

Бот слушает на `127.0.0.1:8770`. Meta доставляет только на **HTTPS** и не
принимает самоподписанный сертификат, поэтому что-то должно поставить настоящий
перед ним. Туннель — обычный ответ: ни открытого порта, ни DNS, ни домена.

**`comodor whatsapp connect` делает это за вас**, если установлен `cloudflared` —
он запускает туннель, читает из него адрес и показывает, что вставить. Чтобы
запустить один самостоятельно:

```bash
cloudflared tunnel --url http://127.0.0.1:8770
comodor whatsapp connect --url https://something.trycloudflare.com/whatsapp
comodor whatsapp webhook
```

**Быстрый туннель получает новый адрес при каждом запуске.** Это нормально
во время настройки и неверно для бота, которому суждено работать постоянно:
Meta продолжает доставлять по адресу, который вы ей дали, поэтому после
перезапуска ничего не приходит и ничего не говорит почему.
`comodor whatsapp start --tunnel` предупреждает, когда адрес переехал.

Для адреса, который остаётся, создайте именованный туннель один раз — нужен
бесплатный аккаунт Cloudflare:

```bash
cloudflared tunnel login
cloudflared tunnel create comodor
cloudflared tunnel route dns comodor comodor-hooks.example.com
```

Всё остальное, что завершает TLS и перенаправляет на `127.0.0.1:8770`, работает
так же.

```
  Callback URL   https://something.trycloudflare.com/whatsapp
  Verify token   Kq3nP…
```

Вставьте оба в **WhatsApp → Configuration** в панели, затем подпишите
приложение на поле **messages**. Meta сразу вызывает URL один раз, чтобы
проверить его; бот отвечает на это рукопожатие сам.

Обратный прокси, который вы уже запускаете, работает так же — всё, что
завершает TLS и перенаправляет на `127.0.0.1:8770`.

### 3. Привяжите ваш номер

```bash
comodor whatsapp pair
```

Он печатает шестизначный код. Отправьте его на бизнес-номер из WhatsApp, и ваш
номер добавлен. Код срабатывает один раз и истекает через пять минут.

**Бизнес-номер — это телефонный номер**, а незнакомцы пишут телефонным номерам
как само собой разумеющееся. Поэтому он отвечает на фиксированный список, а все
остальные получают **тишину** — не отказ. Номер, который говорит «вам не
разрешено», сообщил незнакомцу, что стоит попробовать снова.

```bash
comodor whatsapp status         # кто может с ним говорить
comodor whatsapp forget 15551234567
comodor whatsapp forget all
```

Список сравнивается как цифры, поэтому `+1 555…`, `001 555…` и `1555…` — один
человек, а не три.

## Что он может и чего не может

**По умолчанию он читает и планирует, и ничего не меняет.** Сессия WhatsApp
удерживается в режиме плана, что бы ни было задано терминалу, по той же причине,
что и Telegram: одобрить команду оболочки большим пальцем, в очереди, — решение,
принятое с меньшим вниманием, чем то же одобрение у клавиатуры.

```bash
comodor whatsapp writes on
comodor whatsapp writes off
```

Это терминальная команда намеренно. Бот, который мог бы расширять собственные
разрешения, нуждался бы лишь в чьём-то телефоне.

## Кнопки

WhatsApp разрешает **три** кнопки ответа по двадцать символов или одну кнопку,
открывающую список из **десяти** строк. Это жёсткие пределы — Meta отклоняет
всё сообщение, а не обрезает его — поэтому меню — список, и в нём ровно десять
строк:

| | |
|---|---|
| **New chat** | Забыть разговор до сих пор |
| **History** | Открыть заново прежний разговор |
| **Mode** | Действовать, планировать или болтать |
| **Status** | Модель, папка, контекст, траты |
| **Model** | Переключиться на другую |
| **Folder** | В каком проекте он работает |
| **Skills** | Установить или удалить один |
| **Rules** | Чему он научился из ваших поправок |
| **What it may do** | Может ли он править и исполнять |
| **Help** | Что делает всё |

Пока задача выполняется, предлагается только **Stop**: на экране такой узости
нет места, чтобы держать элемент управления приглушённым.

Более длинные списки — модели, навыки, история — разбиваются на страницы по
восемь, потому что две строки навигации считаются против десяти.

## Две вещи, которые вас удивят

**Он не может править сообщение.** Telegram транслирует ответ, переписывая одно
сообщение по мере поступления ответа. У WhatsApp нет правки, и сообщение на
каждый токен было бы сотней уведомлений за один вопрос. Поэтому ход говорит
одну строку в начале, изредка высказывается, пока работает, и отправляет ответ,
когда он есть.

**Есть окно длиной в день.** Meta разрешает свободные сообщения только в
пределах двадцати четырёх часов после *вашего* последнего сообщения. Если
длинная задача заканчивается после этого, бот не может вам сказать — он пишет
это в свой журнал, а новая запись в него окно открывает заново.

## Запуск

Ровно как Telegram:

```bash
comodor whatsapp start                # здесь, удерживая этот терминал
comodor whatsapp start --tunnel       # и поднять туннель вместе с ним
comodor whatsapp start --background   # отсоединённо; переживёт закрытие
comodor whatsapp stop
comodor whatsapp service install      # стартует при входе, переживёт перезагрузку
comodor whatsapp service show         # прочитать unit, прежде чем доверять
```

Журнал — `whatsapp.log` рядом с вашей конфигурацией, дополняется, а не
заменяется.

**Пользовательская** служба на каждой платформе — systemd, launchd, Task
Scheduler — никогда не системная. Это агент, читающий и пишущий ваши файлы с
вашими учётными данными, и больше полномочий, чем у человека, владеющего этими
файлами, не даёт ничего.

## Как он устроен

Без новой зависимости. Cloud API — это `POST /messages` через HTTP-клиент,
который у этого проекта уже есть, а webhook — `http.server` из стандартной
библиотеки.

Конечная точка отвечает Meta **до** выполнения работы. Meta повторяет всё, на
что не получила 200 в течение секунд, а ход агента занимает минуты — webhook,
который ждёт, получит одно и то же сообщение пять раз.

Id сообщений запоминаются, поэтому повторная доставка, которая всё же приходит,
не становится вторым ходом.

## Чего он не будет делать

- Отвечать тому, кто не привязан, или объяснять почему.
- Принимать webhook, который не может проверить. Без секрета приложения ничто
  не проверяется, и `comodor whatsapp status` говорит об этом жёлтым.
- Брать токен, номер или разрешённую учётную запись из `.comodor/config.json`
  проекта. Репозиторий, который мог бы добавить своего автора в этот список,
  был бы задним входом.
- Править что-либо до `whatsapp writes on`.
- Печатать токен. Он вырезается из каждой вызванной ошибки.
