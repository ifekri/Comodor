# متصفح حقيقي

ليس مجرّد جامع لصفحات الويب. متصفح مثبَّت فعلًا على الجهاز — يشغّل JavaScript، ويحفظ الكوكيز، ويستطيع تسجيل الدخول.

---

## ما الذي يستخدمه

Chrome أو Chromium أو Edge أو Brave، أيّها موجود على الجهاز. **لا يُنزَّل شيء إطلاقًا.** يشغّل متصفحًا واحدًا داخل ملف تعريف خاص به لم يُسجَّل دخوله إلى أي شيء، ويغلقه عند انتهاء الجلسة.

إذا لم يكن أيٌّ منها مثبتًا، يتراجع الأمر `browse` إلى متصفح نصّي لا يزال قادرًا على الإجابة عن معظم الأسئلة حول الصفحة. وكلاهما يُسمّى `browse`، لأن الاختيار بين شيئين يحملان الاسم «browser» هو دورٌ لا يجدر بالفرض أن ينفقه.

---

## ما الذي يعود نتيجةً

ليست لقطة شاشة. بل العنوان، والنص المقروء، و**قائمة مرقّمة بعناصر التحكم الفعلية الظاهرة على الشاشة**:

```
  Sign in — Example
  ─────────────────────────────────────────────
  Sign in to your account. New here? Create one.

  [1]  textbox   Email
  [2]  textbox   Password
  [3]  button    Sign in
  [4]  link      Forgot your password?
```

يتصرّف النموذج على أحد هذه العناصر برقمه. وتُرشَّح هذه القائمة لتشمل ما هو مرئي ومسمّى وضمن الشاشة وغير مكرَّر فقط — وهي بذلك أصغر بكثير من شجرة إمكانية الوصول (accessibility tree)، ومن حيث القياس أصغر من لقطة شاشة للصفحة نفسها.

لا تُلتقط لقطة شاشة إلا إذا كان السؤال بصريًا — كالتخطيط أو التنسيق أو رسم بياني — لأن الصورة تكلّف الشيء نفسه في كل مرة ولا يمكن اختصارها.

## الأفعال

| | |
|---|---|
| `open` | الانتقال إلى عنوان URL |
| `click` | عنصر تحكم، برقمه |
| `type` | الكتابة في حقل، برقمه |
| `scroll` | التمرير لأعلى أو لأسفل |
| `back` | الصفحة السابقة |
| `read` | قراءة الصفحة من جديد، بعد تغيّر شيء ما |
| `look` | لقطة شاشة، عندما يكون السؤال عن المظهر |
| `script` | تشغيل JavaScript وإرجاع قيمته |

## مشاهدة أثناء العمل

```json
{ "browser": { "headless": false } }
```

نافذة مرئية، لتشاهد ما يفعله.

> كان هذا الإعداد يُتجاهَل سابقًا — إذ لم يكن `browser` مسجَّلًا كقسم في الإعدادات، فكان كل إعداد `browser` يعمل بصمت دون أي أثر. أُصلح ذلك في الإصدار 0.9.0.

---

## استخدام جلسة سجّلت الدخول إليها مسبقًا

بدلًا من تسليم ملف التعريف الخاص بك، شغّل متصفحك بنفسك مع منفذ DevTools ووجّه Comodor إليه:

```bash
chrome --remote-debugging-port=9222
```

```json
{ "browser": { "port": 9222 } }
```

يتصل بذلك المتصفح ويستخدم التبويبات والكوكيز الموجودة فيه مسبقًا. أغلق المنفذ عندما تنتهي — فأي شيء على جهازك يستطيع استخدامه.

## جميع الإعدادات

```json
{
  "browser": {
    "executable": "",
    "headless": true,
    "width": 1280,
    "height": 800,
    "port": 0
  }
}
```

| | |
|---|---|
| `executable` | متصفح محدَّد. الفراغ يعني البحث في المواضع المعتادة |
| `headless` | مخفي افتراضيًا، حتى لا يسرق التركيز |
| `width`, `height` | النافذة |
| `port` | الاتصال بمتصفح شغّلته أنت بدلًا من تشغيل واحد جديد |

لا يستطيع المستودع ضبط أيٍّ من هذه الإعدادات — فالقيمة `browser.executable` تسمّي ملفًا تنفيذيًا يُطلَق. [الأمان](safety.md#what-a-repository-may-set).

---

## `browse` أم `web_fetch`؟

| | |
|---|---|
| `web_fetch` | الصفحة مستند. يُخلَّصها إلى نص. منخفضة التكلفة |
| `browse` | الصفحة تطبيق. تحتاج JavaScript أو تسجيل دخول أو نقرة |

يُخبَر النموذج أن يفضّل `web_fetch` وأن يلجأ إلى `browse` عندما لا تكفي الأولى.

---

## داخل حاوية

تأتي صورة Docker مع Chromium والخطوط اللازمة للعرض معه. لا يستطيع صندوق الحماية الخاص بـ Chromium أن يبدأ داخل حاوية يحجب ملف seccomp الخاص بها مساحات أسماء المستخدمين، لذا يكتشف Comodor ذلك ويعيد المحاولة دون الصندوق الداخلي — مع الحفاظ على حصر الحاوية نفسها، فهو الحد الفاصل الحقيقي. [Docker](docker.md).

---

## تحت الغطاء

بروتوكول Chrome DevTools عبر WebSocket مبني يدويًا. لا توجد اعتماديات: تأطير RFC 6455 لا يزيد على مئة سطر وهو جزء من الحزمة، تمامًا كما هو الحال مع عميل HTTP وقارئ SSE.
