# السلامة والأذونات

ما يستطيع Comodor فعله بجهازك، وما يسأل عنه أولًا، وما لن يفعله مهما قلت.

---

## النسخة المختصرة

- **القراءة صامتة.** إدراج الملفات، وقراءتها، والبحث — بلا مطالبة.
- **الكتابة تسأل.** وترى الفرق diff قبل أن يقع.
- **تشغيل أمر يسأل بصوت أعلى**، وكذلك الوصول إلى الشبكة أو قيادة شاشتك.
- **كل ما هو قابل للعكس يعكسه `/undo`.**
- **لا يستطيع أن يغادر مجلد المشروع** إلا إذا أوقفت ذلك.
- **المستودع لا يستطيع تغيير أيًا مما سبق.**

---

## طبقات المخاطر

تصرح كل أداة عن واحدة. والطبقة تحدد ما يحدث قبل تشغيلها.

| الطبقة | الأدوات | ما يحدث |
|---|---|---|
| **safe** | `read_file`، `list_dir`، `grep`، `glob`، `todo_write` | تعمل |
| **write** | `write_file`، `edit_file` | تسأل، مع فرق diff |
| **dangerous** | `run_shell`، `run_python`، `web_fetch`، `web_search`، `browse`، `computer` | تسأل |

في **نمط الخطة**، يُرفض أي شيء فوق `safe` قبل تشغيله. ويُفرَض ذلك على طبقة
الأذونات، لا بطلب الاعتدال من النموذج.

وفي **نمط الدردشة** لا أدوات على الإطلاق.

## المطالبة

```
  Run  pytest tests/ -x
  ────────────────────────────────────────────
  in ~/projects/api-server

  [a] allow   [A] allow always this session   [d] deny
```

يتذكر `A` خلال الجلسة، بحسب نوع الشيء — فالسماح بالكتابات لا يسمح بالأوامر،
والسماح بـ `pytest` لا يسمح بـ `rm`.

للتوقف عن السؤال:

```
/approve writes      files yes, commands still ask
/approve shell       commands yes, files still ask
/approve all         everything
```

أو دائمًا، في إعدادك:

```json
{
  "safety": {
    "auto_approve_writes": true,
    "auto_approve_shell": false
  }
}
```

### الرفض يعلّمه

إن الرفض أوضح إشارة تفضيل تجمعها الواجهة على الإطلاق. وذهابه إلى محرك التعلم
يقلل احتمال أن يقترح الوكيل الشيء نفسه مرة أخرى. فالرفض ليس جهدًا مهدرًا.

---

## نقاط الاسترجاع و`/undo`

كل ملف يكتبه الوكيل يُحفَظ أصلًا كنقطة استرجاع — المحتويات السابقة، محفوظة تحت
`.comodor/checkpoints/` في المشروع.

```
/undo
```

يستعيد آخر ملف غيّره. وهذا يعمل سواء وافقت على الكتابة أم لا، وسواء كان
الموافقة التلقائية قيد التشغيل أم لا. وهو سبب كون `/approve all` أمرًا معقولًا.

وأوقفه إن اضطررت:

```json
{ "safety": { "checkpoints": false } }
```

لا يوجد سبب وجيه لذلك.

---

## حد مساحة العمل

يجوز للوكيل أن يقرأ ويكتب **داخل مجلد المشروع ولا مكان آخر**.

ويُجد جذر المشروع بالسير صعودًا من حيث بدأت حتى يقول شيء «هذا مشروع» — فـ
`.git` أو `pyproject.toml` أو `package.json`. ويُعرض عليك ويُسأل، مرة لكل مجلد:

```
  Work in  /home/you/projects/api-server ?
```

وتتذكَّر المجلدات الموافق عليها. ويسمّي `--cwd` واحدًا مباشرة ولا يسأل.

```json
{ "safety": { "workspace_only": true } }
```

وإيقاف هذا يتيح للوكيل أن يمس نظام ملفاتك كله. وهو ممنوع على إعداد المستودع
لهذا السبب بالضبط.

---

## الأوامر التي لن يشغّلها

بعض الأشياء تُرفض قبل ظهور أي مطالبة، لأنه لا ينبغي لمطالبة أن تقنع إنسانًا
بواحد منها في نهاية جلسة طويلة:

```
rm -rf /     rm -rf ~     mkfs        dd if=      shutdown
reboot       format c:    del /f /s /q c:         :(){
> /dev/sda   chmod -R 777 /
```

والقائمة الكاملة هي `safety.deny_commands`. وأضف ما تريد منها:

```json
{
  "safety": {
    "deny_commands": ["terraform destroy", "kubectl delete namespace"]
  }
}
```

و`safety.allow_commands` في الاتجاه الآخر — أوامر لا تسأل قط:

```json
{ "safety": { "allow_commands": ["git status", "pytest", "ls"] } }
```

## مفاتيحك

**أين تسكن.** في `~/.comodor/config.json` الخاص بك، المكتوب بأذونات المالك
فقط، أو في بيئتك. ولا مكان آخر.

**أين لا تذهب أبدًا.** لا إلى إعداد مستودع. ولا إلى الواجهة. ولا إلى سجل. ولا
إلى `repr` — فتلك كانت عيبًا حقيقيًا، وُجد وأُصلح: كان أي تتبع استثناء يسمّي
Config يطبع المفتاح، وpytest يطبع تتبعات الاستثناء باستمرار.

**المفتاح في بيئتك يبقى هناك.** فإذا صادرت `ANTHROPIC_API_KEY` بدل حفظها، فلن
ينسخها `/save` إلى ملف إعدادك. والتصدير بدل الحفظ قرار، ويُحترم.

**الإخفاء.** يُقنَّع أي شيء يشبه أحد مفاتيحك في مخرجات الأدوات، وفي النسخة
النصية، وفي التصديرات. وهو يعمل على النص. ولا يستطيع قراءة البكسلات — راجع
[استخدام شاشتك](computer.md#what-goes-to-the-model).

## ما يجوز لمستودع أن يضبط

يُقرأ `.comodor/config.json` الموجود في مشروع من أي دليل بدأت منه — وهو، لوكيل
برمجة، يعني *من مستودع كتبه شخص آخر، فور استنساخه*.

لذلك هو مقيد بالأشياء التي لا يمكن تحويلها ضدك:

| يجوز لمشروع أن يضبط | |
|---|---|
| `provider`، `model` | أي نموذج يستخدم |
| `agent` | النمط، والحلقة، والميزانيات، والحرارة، وحجم المخرجات |
| `ui` | السمة، والحدود، والشعار |
| `learning`، `skills` | ما إذا كانت قيد التشغيل، وحدودها |
| `mcp.servers` | أي خوادم يستخدم — **وصولًا مطفأة** |

| لا يجوز لمشروع أن يضبط | لأن |
|---|---|
| `providers.*.base_url` | مفتاحك سيذهب إلى خادمهم في أول طلب |
| `safety.*` | يستطيع إيقاف سؤال الوكيل، أو إفراغ قائمة الرفض |
| `agent.system_prompt_extra` | تعليمات تُحقن بسلطتك |
| `browser.executable` | يسمّي ملفًا تنفيذيًا يشغّله الوكيل |
| `computer.*` | يطلب من الجهاز الذي استُنسخ عليه للتو فأرتك |
| `mcp.enabled` | التصريح بخادم اقتراح؛ وبدء واحد قرار |

وهذه **قائمة سماح**، لا قائمة رفض، فالإعداد الذي يضاف العام القادم غير موثوق
حتى يقرر شخص غير ذلك — وهي الجهة الصحيحة أن تخطئ فيها.

وتقال الرفضات بصوت عالٍ:

```
config: this project cannot set safety, computer — only your own can
```

فالتجاهل الصامت لملف شخص ما هو ما يكسب ملف الإعداد سمعة أنه لا يعمل.

## السقوف

ثلاثة، وتنطبق على كل مهمة:

```json
{
  "agent": {
    "max_steps": 24,
    "max_seconds": 900,
    "max_cost_usd": 2.0
  }
}
```

**سقف المال لا يعمل إلا لنموذج له سعر معلَن.** فلنموذج لا يعرفه جدول الأسعار
يقرأ عدّاد الكلفة صفرًا ولا يعمل الحد قط. ويقول Comodor ذلك بدل أن يدعك تظن
أن لديك سقفًا:

```
the $2.00 spend limit cannot be enforced for gpt-4o — no published rate is
known, so the cost meter reads zero. The step and time limits still apply.
```

يُقال في بداية جلسة وفي `comodor doctor`. راجع [التكلفة](cost.md).

## الوكلاء الفرعيون

يشغّل `delegate` وكيلًا فرعيًا في git worktree — نسخة معزولة من المستودع.
لا ذاكرة له، ولا يستطيع التفويض أبعد، و**لا يُعطى الشاشة**: فالوكيل الفرعي
العامل في worktree لا سبب له إلى أخذ فأرك.
