# من Slack

الوكيل نفسه، داخل مساحة عملك: أرسل إليه مهمة، وشاهده يعمل، وأجب عن أسئلته — دون أن تفتح طرفية.

```bash
comodor slack manifest              # the app definition to paste into Slack
comodor slack connect               # the two tokens, checked as you paste them
comodor slack pair                  # add your account
comodor slack start --background    # run it
```

نحو خمس دقائق، ولا يوجد **عنوان علني يدبّره** — وهذا ما يفصل هذا عن [WhatsApp](whatsapp.md).

يشغّل جلسة الوكيل نفسها التي تشغّلها الطرفية والمتصفح وبوت Telegram. والمهمة التي تبدأ هنا تتعلّم الدروس نفسها وتستقر في السجل نفسه.

## لماذا هذا سهل

لدى Slack طريقتان لتسليم الأحداث. فـEvents API يرسل إلى عنوان URL، ما يعني عنوان HTTPS علنيًا وشهادة ونفقًا — كل العمل الذي يجعل WhatsApp صعبًا.

**Socket Mode** يقلب ذلك: يطلب التطبيق من Slack عنوان websocket ويتصل *نحو الخارج*. فلا شيء يلزم أن يكون قابلًا للوصول إليه من الإنترنت، ولا عنوانًا يلزم إبقاؤه محدَّثًا. هذه هي الحيلة كلها، وهي سبب جلوس Slack بجوار Telegram لا بجوار WhatsApp.

والشيء الثاني المُعين هو **manifest التطبيق**. يتيح Slack وصف التطبيق في مستند YAML، فبدلًا من مطاردة أحد عشر مربع اختيار موزعة على أربع صفحات إعدادات، يكون التطبيق كله — الاسم، والنطاقات، والأحداث، وSocket Mode مفعّل مسبقًا — لصقة واحدة.

## الإعداد

### 1. أنشئ التطبيق

```bash
comodor slack manifest
```

يطبع ذلك الـmanifest والرابط. وعلى [api.slack.com/apps](https://api.slack.com/apps?new_app=1)، اختر **From a manifest**، وحدد مساحة عملك، وألصقه، وأنشئ — ثم **Install to Workspace**.

### 2. الرمزان

وهما لا يتبادلان موقعهما، وخلطهما هو أشيع سبب للفشل هنا. فيرفض Comodor كلًّا منهما في موضع الآخر بالاسم، بدلًا من أن يجيب Slack بـ`invalid_auth` بعد ساعة.

| | | |
|---|---|---|
| `xoxb-…` | **Bot token** | OAuth & Permissions. يفعل كل ما يفعله البوت |
| `xapp-…` | **App-level token** | Basic Information → App-Level Tokens، بالنطاق `connections:write`. يفتح المقبس، ولا شيء غيره |

```bash
comodor slack connect
```

وبلا وسائط يأخذك على كليهما ويتحقق من كل واحد عند وصوله — رمز البوت يُقارَن عبر `auth.test`، ورمز التطبيق بفتح مقبس (socket) به فعلًا. فالرمز الخاطئ جملة الآن لا لغز في الأسبوع القادم.

### 3. اقرن حسابك

```bash
comodor slack pair
```

يطبع رمزًا من ستة أرقام. أرسله إلى Comodor برسالة مباشرة فيُضَف حسابك. والرمز يعمل مرة واحدة وينتهي بعد خمس دقائق.

**قد تحوي مساحة العمل مئات الأشخاص**، وهذا وكيل يقرأ ملفاتك ويكتبها. لذا يجيب عن قائمة ثابتة من معرّفات مستخدمي Slack ويتجاهل كل من سواها.

```bash
comodor slack status
comodor slack forget U01234567
comodor slack forget all
```

## أين يجيب

**في رسالة مباشرة**، دائمًا.

**في قناة، فقط عندما يُذكَر.** فالبوت الذي يرد على كل رسالة في قناة مشتركة بوت يزيله أحدهم بعد الظهر.

**في الخيط الذي خُوطِب فيه.** فالسؤال المطروح في خيط يُجاب عنه في ذلك الخيط، لا في القناة أمام الجميع.

ورسائله الخاصة لا تُجاب أبدًا — فالبوت الذي يرد على نفسه حلقة لا نهائية عليها حد معدل.

## ما يستطيعه وما لا يستطيعه

**افتراضيًا يقرأ ويخطط ولا يغيّر شيئًا.** فجلسة Slack تبقى في وضع الخطة مهما كان ضبط الطرفية، والسبب نفسه في القنوات الأخرى: الموافقة على أمر صَدَفة من هاتف، في طابور، قرار تُبذَل فيه انتباه أقل من الموافقة نفسها على لوحة مفاتيح.

```bash
comodor slack writes on
comodor slack writes off
```

أمر طرفية عمدًا. فالبوت الذي يستطيع توسيع أذوناته بنفسه لن يحتاج سوى حساب Slack لشخص ما.

## الأزرار

Slack أوسع القنوات الثلاث مجالًا — يمكن تعديل الرسائل والأزرار وفيرة — فالرد رسالة واحدة تنمو كلما وصل الجواب، والقائمة كلها تتسع لشاشة واحدة.

| | |
|---|---|
| **New chat** | نسيان المحادثة حتى الآن |
| **History** | إعادة فتح محادثة سابقة |
| **Mode** | التنفيذ أو التخطيط أو الدردشة |
| **Status** | النموذج، المجلد، السياق، الإنفاق |
| **Model** | التبديل إلى نموذج آخر |
| **Folder** | المشروع الذي يعمل فيه |
| **Skills** | تثبيت إحداها أو إزالتها |
| **Rules** | ما تعلّمه من تصحيحاتك |
| **What it may do** | هل يستطيع التعديل والتنفيذ |
| **Help** | ما يفعله كل شيء |

وأثناء تشغيل مهمة لا يُعرَض شيء سوى **Stop**.

## تشغيله

```bash
comodor slack start                # here, holding this terminal
comodor slack start --background   # detached; survives closing it
comodor slack stop
comodor slack service install      # starts at login, survives a reboot
comodor slack service show         # read the unit before trusting it
```

والسجل هو `slack.log` بجوار ملف إعداداتك، يُضاف إليه ولا يُستبدَل.

خدمة **للمستخدم** على كل منصة — systemd وlaunchd وTask Scheduler — لا خدمة نظام أبدًا. فهذا وكيل يقرأ ملفاتك ويكتبها ببيانات اعتمادك، وسلطة أعلى من سلطة صاحب تلك الملفات لا تشتري شيئًا.

## من لوحة المتصفح

`comodor web` → **Admin** → **From your phone** يتولى الربط والإقران والتشغيل والإيقاف لكل هذا دون طرفية. وهذه الضوابط لا تجيب إلا عن الطلبات القادمة من الجهاز الذي يعمل عليه Comodor: فرمز البوت يسلّم التحكم عن بُعد به لمن يملك الرمز.

## كيف بُني

لا اعتمادية جديدة. فـWeb API هو `POST /api/chat.postMessage` عبر عميل HTTP الذي يملكه هذا المشروع مسبقًا، ويعمل Socket Mode فوق عميل websocket المكتوب لقيادة Chrome — ولهذا لم تُضف إضافة Slack أي حزم.

ثلاثة أمور تتخذها حلقة المقبس حذرة تجاهها، وكل منها طريقة يصمت بها بوت دون أن ينتبه أحد:

- **كل مغلّف يُقرّ.** فـSlack يعيد تسليم ما لم يسمع عنه، وبالنسبة لوكيل ينفّذ أوامر فإن رسالة تتحول إلى ثلاثة أدوار ليست مجرد إزعاج.
- **`disconnect` أمر اعتيادي.** فـSlack يبدّل الاتصالات وفق جدول. ومعاملة ذلك كفشل تنتج بوتًا يموت كل بضع ساعات.
- **مساحة العمل الصامتة تتلقى ping أيضًا.** فالحالة الأهم — عدم مراسلة أحد له منذ ساعة — هي بالضبط الحالة التي تفسدها مقبس متساقط.

## ما لن يفعله

- أن يجيب أيًّا لم يُقرن به.
- أن يجيب عن كل شيء في قناة أُضيف إليها.
- أن يأخذ رمزًا أو حسابًا مسموحًا من ملف `.comodor/config.json` الخاص بمشروع. فالمستودع الذي يستطيع إضافة صاحبه إلى تلك القائمة سيكون بابًا خلفيًا.
- أن يعدّل شيئًا قبل `slack writes on`.
- أن يطبع أيًّا من الرمزين. فهما يُحجَبان من كل خطأ يُرفَع.
