# من هاتفك

يمكن قيادة Comodor من بوت Telegram: أرسل إليه مهمة، وشاهده يعمل، وأجب عن أسئلته وأوقفه — دون أن تفتح طرفية.

**يطرح إعداد التشغيل الأول سؤالًا عن هذا.** آخر الأسئلة الستة يعرض ربط بوت، ويتحقق من الرمز لدى Telegram في حينه، ويقرن حسابك قبل انتهاء المعالج. فإن قلت *Not now*، أو كنت تضبط جهازًا مضبوطًا مسبقًا:

```bash
comodor telegram connect <token>   # a bot from @BotFather
comodor telegram pair              # add your account
comodor telegram start             # run it
```

يشغّل جلسة الوكيل نفسها التي تشغّلها واجهة المتصفح. وكل شيء زر؛ أما الكتابة فلنص المهمة نفسها.

## الحصول على بوت

راسل [@BotFather](https://t.me/botfather) على Telegram، وأرسل `/newbot`، وامنحه اسمًا واسم مستخدم ينتهي بـ `bot`. فيرد برمز:

```
1234567890:AAF…
```

```bash
comodor telegram connect 1234567890:AAF…
```

## الإقران

**اسم مستخدم البوت علني.** أي من يعثر عليه يستطيع مراسلته، وهذا البوت يستطيع قراءة ملفاتك. لذا لا يجيب إلا عن قائمة ثابتة من معرّفات مستخدمي Telegram الرقمية، لا عن أحد سواها.

```bash
comodor telegram pair
```

يطبع رمزًا من ستة أرقام. أرسله إلى بوتك على Telegram فيُضَف حسابك. والرمز يعمل مرة واحدة وينتهي بعد خمس دقائق.

وكل من سواك يحصل على **صمت** — لا على رفض. فالبوت الذي يقول «أنت غير مسموح لك» قد أخبر غريبًا أنه موجود، وأنه Comodor، وأن هناك قائمة تستحق الانضمام إليها.

```bash
comodor telegram status         # who may talk to it
comodor telegram forget 12345   # revoke one account
comodor telegram forget all     # revoke everybody
```

## ما يستطيعه وما لا يستطيعه

**افتراضيًا يقرأ ويخطط ولا يغيّر شيئًا.** فجلسة Telegram تبقى في وضع الخطة مهما كان ضبط الطرفية.

وهذا مقصود. فالموافقة على أمر صَدَفة بالإبهام، على هاتف، وفي طابور، قرار تُبذَل فيه انتباه أقل من الموافقة نفسها على لوحة مفاتيح — والنتائج متطابقة.

```bash
comodor telegram writes on      # let it edit files and run commands
comodor telegram writes off
```

ومع تمكين الكتابة يبقى يسأل أولًا، والموافقة زر في الدردشة:

```
Comodor wants to run
  npm test

  ✓  Yes, once
  ✓✓ Yes, and stop asking this session
  ✗  No
```

والالتزام الأوسع ليس أبدًا الزر الأول تحت إبهامك — ففي الهاتف هي متقاربة، و«دائمًا» لا يمكن التراجع عنها.

## الأزرار

يجيب `/start` بالنموذج والمجلد وما يُسمح له بفعله، وبالإعدادات تحتها. فهي على الشاشة الأولى بدلًا من أن تكون خلف زر *Settings*، لأن ما يشير إليه البوت هو أول ما يريد أي أحد أن يعرفه وأول ما يريد أن يغيّره.

| | |
|---|---|
| **New chat** | نسيان المحادثة حتى الآن |
| **History** | إعادة فتح أي محادثة سابقة، كاملة |
| **Stop** | مقاطعة ما هو قيد التشغيل — ويحل محل *New chat* ما دام جاريا |
| **Mode** | التنفيذ أو التخطيط أو الدردشة، كل واحد مكتوب صراحة |
| **Status** | النموذج، المجلد، السياق، الإنفاق |
| **Model** | كل نموذج يقدمه المزوّد؛ انقر للتبديل |
| **Folder** | المشروع الذي هو محصور فيه |
| **Skills** | تثبيت إحداها من المكتبة أو إزالتها |
| **Rules** | ما تعلّمه من تصحيحاتك، وكم قاعدة |
| **Settings** | البقية — التكلفة، وما يجوز له فعله |
| **Help** | ما يفعله كل شيء، دون مغادرة الدردشة |

وعندما يحتاج الوكيل قرارًا يسأل بالأزرار أيضًا — الأسئلة نفسها التي سيسألها في الطرفية، سؤال لكل شاشة، مع خيار **Write my own** لأي شيء لم يخطر بباله.

والقوائم الأطول من شاشة — النماذج، والمهارات، والسجل — تُعرَض على صفحات من ستة في المرة، مع **Previous** و**Next**. فإن Telegram يسعد بعرض ثمانين زرًا، ولن يتصفّها أحد بالتمرير.

## تشغيله

ثلاث طرق، مرتّبة بحسب المدة التي تريدها أن تدوم.

```bash
comodor telegram start                # here, holding this terminal
comodor telegram start --background   # detached; survives closing the terminal
comodor telegram service install      # starts at every login, survives a reboot
```

**في المقدمة** يحتجز الطرفية ويعرض ما يفعله. فهذه هي الطريقة التي تستخدمها أثناء الإعداد، والتي تعود إليها عندما لا يعمل شيء على ما يرام.

**في الخلفية** هي العملية نفسها، منفصلة عن الطرفية التي بدأتها، تكتب في سجل بدلًا من شاشة. فإغلاق الطرفية، أو تسجيل الخروج، أو إنهاء الجلسة — لا شيء منها يحملها معها.

```bash
comodor telegram stop        # end it
comodor telegram status      # is it running, since when, and as which pid
```

والسجل هو `telegram.log` بجوار ملف إعداداتك، ويُضاف إليه ولا يُستبدَل — فسبب توقف البوت ليلة أمس في الأسطر التي كان سيمحوها إعادة التشغيل.

**عند تسجيل الدخول** مهمةُ نظام التشغيل لا مهمتنا: فلا شيء يبدأه برنامج لنفسه ينجو من إعادة تشغيل الجهاز.

```bash
comodor telegram service show        # read the unit before trusting it
comodor telegram service install
comodor telegram service uninstall
```

| | |
|---|---|
| Linux | وحدة systemd **للمستخدم** في `~/.config/systemd/user` |
| macOS | LaunchAgent في `~/Library/LaunchAgents` |
| Windows | مهمة في Task Scheduler تعمل عند تسجيل الدخول |

خدمة على مستوى المستخدم في الأنظمة الثلاثة، وليست على مستوى النظام أبدًا. فخدمة النظام تعمل بحساب root أو SYSTEM، وهذا وكيل يقرأ ملفاتك ويكتبها ببيانات اعتمادك — فسلطة أعلى من سلطة صاحب تلك الملفات لا تشتري شيئًا وكلّف كل شيء إذا أخطأت مرة.

يطبع `service show` الوحدة قبل أن يكتبها `service install`. فلا ينبغي أن يُطلَب من أحد أن يثق بتعريف خفيّة (daemon) لم تُعرَض عليه.

والمجلد مهم في الأنظمة الثلاثة: فالوكيل لا يقرأ ولا يكتب إلا داخل الدليل الذي بدأ فيه، وهو ما سيعمل فيه البوت.

## كيف بُني

لا اعتمادية جديدة. فـBot API هو `getUpdates` في حلقة و`sendMessage`، عبر عميل HTTP الذي يملكه هذا المشروع مسبقًا — فـ`python-telegram-bot` كان سيكون أكبر شيء في العجلة بسبب ذلك.

يُحرَّر الرد بمؤقّت بدلًا من التحرير عند كل توكن. فـTelegram يحتسب ذهابًا وإيابًا لكل تحرير ويحدّ من معدلها، لذا ينتج التحرير عند كل توكن رسالة تُخنَق حتى تصل دفعة واحدة في النهاية.

يحتفظ البوت بإزاحة تحديث ويدفعها إلى الأمام كلما تقدم. ومن دونها، تعيد عملية إعادة التشغيل تشغيل كل رسالة استلمها البوت قط — وهو ما ليس مجرد إزعاج بالنسبة لوكيل ينفّذ أوامر.

## ما لن يفعله

- أن يجيب أيًّا لم يُقرن به، أو أن يقول السبب.
- أن يأخذ رمزًا أو حسابًا مسموحًا من ملف `.comodor/config.json` الخاص بمشروع. فالمستودع الذي يستطيع إضافة صاحبه إلى تلك القائمة سيكون بابًا خلفيًا، وعلى عكس المتصفح أو الشاشة لن يكون على الشاشة ما يُرى به حدوث ذلك.
- أن يعدّل شيئًا قبل `telegram writes on`.
- أن يطبع الرمز. فهو في كل رابط من روابط Bot API، لذا فكل خطأ يُرفَع يُنزَع منه.
